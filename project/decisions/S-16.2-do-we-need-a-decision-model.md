# S-16.2 — Do we need a decision model? A first count

**Answer for now: no.** Brain turns that a typed decision could have handled used about **20 %** of the brain's
usage, under the story's 25 % line. But the sample is one night of test traffic, so count again after S-16.1 on at
least a week of the family's own use. The bigger cost was not decisions at all: **half the brain's usage went on
starting fresh sessions and compacting.**

## What was counted

- **The window:** 2026-10-13 19:58 to 2026-10-14 05:28 UTC, from the first deploy on the NUC to the morning digest.
- **Who sent it:** every message came from build sessions (install checks, live tests, drills). None came from the
  family. This sample cannot show how real people use Marcel.
- **The sources:** 125 triage decisions (`triage.log`) and 28 brain turns in the transcripts of Marcel's brain (9
  sessions) and Pip's (1). Both agree: 11 owner messages, 3 failed tasks, 2 task questions, 1 digest.
- **The measure:** tokens per turn, summed over the turn's model calls, each call counted once. Plan usage is not
  reported per session; `usage_snapshot` mixes every session on the account. So the share is **weighted by Opus
  prices** (input 1, cache write 1.25, cache read 0.1, output 5) as a stand-in for plan usage.

## The numbers

| Brain turns | Turns | Output tokens | Cache read | Weighted share | Share of event turns |
|---|---:|---:|---:|---:|---:|
| A. Status questions ("is anything waiting on me?") | 2 | 963 | 330 k | 7.4 % | 14.9 % |
| B. Follow-up → existing thread | 0 | — | — | 0 % | 0 % |
| C. Worker event the brain only relayed (2 questions, 3 failures) | 5 | 2 197 | 719 k | 12.5 % | 25.4 % |
| **A + B + C: a typed decision could have done these** | **7** | | | **19.9 %** | **40.3 %** |
| D. Needs the brain: start a quest (4), chat (4), digest (1) | 9 | 5 211 | 1 523 k | 29.4 % | 59.7 % |
| E. Start-up seeds (9), compactions (2), one probe | 12 | 3 413 | 894 k | **50.7 %** | — |

- **The share of event turns** leaves out E. Counted that way, A + B + C come to 40 %, over the line. The story asks
  for the share of brain usage, which includes E: 19.9 %.
- **C overstates the saving.** In this sample all three failures were test tasks, so the brain only reported them.
  Its real job there is to decide retry, re-route or ask, which a rule cannot do. Today the "worth a push" choice is
  already a rule (`notify/routing.py`); the brain only words the message.
- **A is cheap to do without a model.** A status question runs `tasks_list` and a reply. The hub could answer it from
  the same data, but recognising the question in free text is the hard part. That is the decision model's whole job.

## What changes in the plan

- No follow-up story to pilot Clef through Workers AI. The owner's OK for a second paid API is not needed yet.
- After S-16.1, count again with `project/decisions/S-16.2-count/` on a week of the family's own use:
  `python3 turns.py <brain transcript folders> > t.json && python3 count.py t.json`.
- Worth a look first, though no story yet: start-up seeds were 9 of 28 turns and half the usage that night. Four
  followed an unexpected stop (deploys, and the 02:51 Claude Code self-update), two were first starts (Marcel and
  Pip), two were fresh starts on request (rollover drills) and one was the daily rollover. A fresh brain re-reads its
  seed, and turns reload deferred tools (`ToolSearch` ran in 13 of 16 event turns). Fewer restarts, or a smaller
  seed, saves more than a decision model would.
