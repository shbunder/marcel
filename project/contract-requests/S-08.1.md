# Contract request — S-08.1 (notifier, ntfy backend, routing)

Nothing blocks the story. This answers `S-04.5.md` § 1 and asks for one small change.

## 1. A "something broke" push about no one task (answers S-04.5 § 1)

**What.** `PushNotification.deep_link` is required and must be `marcel://task|message|approval/<id>`.
"Marcel cannot reach the NUC" and runner warnings are about the system, not one task.

**What the hub does now (S-08.1).** It stays inside the contract. A push about no one task opens:

1. the task that changed last — when the runner drops, the watcher has just marked the affected NUC
   tasks `unknown`, so this is usually one of them;
2. else the newest message;
3. else nothing is pushed, and the log says why (a fresh hub with no task and no message).

The all-clear ("The NUC is back") uses the same link and collapse key, so it replaces the alert.

**Proposed change.** Add `marcel://status` to the `deep_link` pattern (a system status screen in the
app showing `GET /health`), and use it for every `broke` push without a `task_id`. The hub change is
one line in `notify/pusher.py` (`_stand_in_link`). Affects: S-08.1 (hub), the iOS deep-link router.
