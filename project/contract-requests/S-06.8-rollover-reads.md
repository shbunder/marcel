# Contract request — a rollover's new brain may read before its hand-over

**What.** `contracts/brain-api.yaml`, the `X-Marcel-Session` rule (lines 18–19): "It must be a conversation's
`brain_session_id`". Add: "or, for `GET` requests only, the new brain of a rollover that has not said hello yet (the
session the hub waits for, or the one the runner lists under the agent's brain name while that rollover's spawn has
not returned). It reads as its agent's main conversation; any other method answers 401 `unknown_session`."

**Why.** Found live on the NUC (2026-10-13): a rollover's new brain runs its `SessionStart` hook (`brain_context.py`,
`GET /brain/tasks`) before its channel hello hands it the conversation, so all six tries got 401 and it started
without its open threads (it then called a stopped task open). The fresh-start path was fixed by `BrainKeeper.claim`;
this covers the rollover path without handing the conversation over early.

**Who reads it.** The hub (`brain_api.require_brain`, `BrainKeeper.incoming`, shipped with tests) and the plugin's
`brain_context.py` (unchanged). No response shape changes.
