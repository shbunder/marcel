# Contract request — S-03.7: say why a usage reading is stale

**What:** an optional `reason` (string) on `UsageReading` in `contracts/runner-api.yaml`, set when `stale` is true
because the latest read failed: the probe's plain message, e.g. "Claude Code is not using the Claude subscription:
… Log in again on the NUC: run claude, then /login."

**Why:** on 2026-10-14 the login refresh failed at 02:52 and `/usage` showed the cost view until about 05:02. The
runner logged it once; `GET /usage` answered `200` with `stale: true` and the old numbers, so the hub's usage guard
and the app saw "stale" with no cause. `UsageReading` has `additionalProperties: false`, so the runner cannot add
the cause itself (only the `503 no_reading` body carries a `detail`). With `reason`, the hub can tell the owner what
to do ("log in again") instead of a silent stale reading. A logged-out Claude Code also stops every new session, so
this is the first sign the owner can act on.

**Proposed change:** `UsageReading.properties.reason: { type: string, description: Why the reading is stale, when the
latest read failed. Absent when it is fresh. }`; not required. Minor version bump of runner-api. Readers: the hub's
`usage.py` (shows it in `/api/usage` and, if wanted, posts it once to the owner), runner `usage.py` (sets it).
