# Contract requests from S-08.2 (APNs backend)

Against `contracts/app-api.yaml`. The hub follows the contract as written; this is a gap it had to fill.

1. **`PushTarget.apns_token` has no format.** The contract allows any string. The hub now refuses
   (`400 bad_request`) a token that is not hex of 64 to 200 characters, because Apple answers
   `BadDeviceToken` to anything else and the token sits in the request path to Apple. Add
   `pattern: '^([0-9a-fA-F]{2}){32,100}$'` (or the same in words) to `PushTarget.apns_token`, so
   the iOS app knows to send the token hex-encoded.
