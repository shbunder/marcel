# Contract request from S-02.6 (mock hub: projects, items and boards)

Two small gaps found while building the mock against the S-02.5 contract. Neither blocks S-02.6; the mock
works around both.

## 1. List and content operations take numbers in the query but list no 400

**What.** `listMessages`, `listTasks`, `listTaskEvents`, `listArtifacts` (all take `limit`, and
`listTaskEvents` also `after`) and `getArtifactContent` (`version`) document only 200, 401 and 404.
A non-numeric or out-of-range value (`?limit=ten`, `?limit=0`, `?after=-1`, `?version=x`) has no
documented answer.

**Why.** The mock (and the real hub) must answer something; a 500 is wrong. The mock now answers 400 in
the `Error` shape with code `bad_request`, which is undocumented for these operations.

**Proposed change.** Add `'400': { $ref: '#/components/responses/BadRequest' }` to those five operations.
Not breaking.

## 2. The examples point at a project the contract never shows

**What.** `Task.example` uses `project_id: prj_inbox`, and `TaskPage.example` and `Artifact.example` use
`prj_01J9ZM1`, but the only `Project` example is `prj_01JA0A1` (Energy contracts). There is no example of
the inbox project or of `prj_01J9ZM1`, nor of their boards.

**Why.** The mock seeds from examples. It now makes up `Inbox` (`prj_inbox`, board `art_board_inbox`)
and `Marcel dev` (`prj_01J9ZM1`, board `art_board_marcel_dev`) so every example points at something
that exists.

**Proposed change.** Either add an `examples` list to `Project` with the inbox and `prj_01J9ZM1`, or say
in the `listProjects` description what the inbox project looks like (name, slug `inbox`, id
`prj_inbox`). Not breaking.
