# Contract request — S-04.6 (channel gateway)

Nothing blocks the story. Three gaps the hub works around today.

## 1. A permission prompt from the brain or a side thread has nowhere to go

**What.** `Approval.task_id` is required, and an approval card belongs to a task. The brain and side
threads are Claude Code sessions too, and can hit a permission prompt. The protocol also says a
denial's note goes "as a `user_message` to the brain or a side thread", which implies such cards.

**What the hub does today.** It drops a `permission_request` from a brain or side session and logs
it. The session waits at its prompt until someone answers it in a terminal.

**Proposed change.** Either state that the brain and side threads never prompt (they run in a mode
where Marcel's own tools are pre-allowed and nothing else asks), or make `Approval.task_id`
optional and add `conversation_id`, so the hub can open a card for them.

## 2. No way to tell a session a call was refused

**What.** `Artifact.artifact_id` says "the hub answers an unknown id … with an error ack", but
`CallAck` has only `call_id` and `duplicate`. The same gap exists for a frame a session may not
send (a worker's `reply`).

**What the hub does today.** It stores nothing and sends no ack, so the server's tool call returns
"queued" after 10 s and the call is re-sent after every reconnect. `artifact_id` is kept in the
artifact's `meta_json` until S-04.11 stores versions.

**Proposed change.** Add `error: {code, message}` to `CallAck`; the server's tool returns the
message to the session, and drops the call.

## 3. Brain and side session ids: who records them

**What.** The hub accepts a brain or side session only when `Conversation.brain_session_id` holds
its id. Nothing in the runner contract says how the hub learns the id of a brain the runner
spawned or a side thread it forked (the runner's `/events` report every session, but nothing maps
a brain session to its conversation).

**What the hub does today.** It reads `brain_session_id`; nothing writes it yet (brain stories,
S-06.x, will).

**Proposed change.** None to the contract if S-06.x writes `brain_session_id` when it spawns or
forks; worth a line in `channel-protocol.md` § Where it connects naming who does.
