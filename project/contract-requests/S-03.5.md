# Contract request — S-03.5 (resume, fork, worktrees)

S-03.5 follows `runner-api.yaml` 0.1.5 and changes nothing in `contracts/`. These answers are not
listed in the contract; the runner gives them today and asks for them to be written down.

1. **Resume: more answers than 400/404/409.** It also answers `409 cap_reached` (waking a worker
   at the cap: it runs again, so it counts, like a spawn), `422 no_supervisor | exited |
   channel_skipped | channel_timeout`, and `503 claude_timeout | claude_unavailable`. Proposed: list
   them on `/sessions/{id}/resume` with the same wording as spawn.
2. **Fork: `400 bad_request` and `503`.** A bad `ForkRequest` body is 400; `claude` not answering is
   503, as for spawn. Proposed: add both to `/sessions/{id}/fork`.
3. **No route to remove a task's worktree.** `Workspaces.remove_worktree` exists (it keeps the branch
   unless asked), but the hub cannot call it. Proposed: `DELETE /workspaces/{repo}/{task_id}` (or a
   `cleanup` flag on stop) once F04 decides when a task's worktree goes away.
4. **`clone_failed` covers every workspace step.** The clone, the fetch, the worktree, the plugin
   install and the "tracked files changed" check all answer `422 clone_failed`, with git's or
   Claude's words in `detail`. Proposed: say so in the spawn 422 description, or split out
   `worktree_failed` and `plugin_failed` if the hub needs to tell them apart.
5. **`RepoSpec.task_id` and `base` have no pattern.** The runner accepts `task_id`
   `^[A-Za-z0-9_][A-Za-z0-9_-]{0,59}$` (it becomes a folder and part of a branch name) and a `base`
   that is a plain branch name (no leading `-`, no `..`, no trailing `/`, `.` or `.lock`). `url` must be
   `https://host/path` without a user or password. Proposed: put these patterns in `RepoSpec`.

Not a contract gap, for the lead: `sessions.spawn_argv` (S-03.2) still passes only `reply` and
`report` to `--allowedTools` for brain and side spawns. The contract says they also get the brain
tools by name. Resume and fork pass them (`resume.allowed_tools`); spawn should use the same function.
