# Contract request — S-09.2 (digests)

S-09.2 sends the `digest_due` system event and announces the published digest; nothing in `contracts/` was
changed. Two gaps the lead may want to close:

1. **The `digest_due` event's `data` is not described** (`channel.schema.json` `SystemEvent.data`). Its
   description covers `handback` only; the example shows `{digest: "evening"}`. The hub sends
   `{digest, facts, artifact_id?}`: `digest` is `morning | evening | weekly | usage` (`usage` only when the owner
   moved the usage report away from the evening digest's time), `facts` is the facts bundle (its fields are in
   `hub/README.md` § Digests and the `digest` skill), and `artifact_id` names the agent's digest board once it
   has one.
   Proposed: add "For `digest_due`: `{digest, facts, artifact_id?}`" to `SystemEvent.data`'s description, and the
   enum of `digest` values. A full JSON schema for `facts` can wait until the bundle has settled on the NUC.

2. **The digest board is a `doc` in the inbox, not a `board`.** B-35/B-36 call the morning digest "a board
   artifact", and S-04.11 says "published as the agent's board artifact". `ArtifactKind.board` is the hub-built
   project board (`dashboard.schema.json`), which the brain cannot publish (brain-api refuses it). So the brain
   publishes a `doc` (Markdown, as the `digest` skill says) and each digest is a new version of it.
   Proposed: confirm this in `app-api.yaml` (`ArtifactKind` description: "the agent's digest board is a `doc`"),
   or add an agent-level board kind if the app should show it differently (S-12.3's "digest: the morning board as
   an `ArtifactCard`" works with a `doc` as it is).
