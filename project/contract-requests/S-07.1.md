# Contract requests from S-07.1 (cloud task lifecycle)

Against `contracts/session-api.yaml`. The hub follows the contract as written; these are gaps it
had to fill.

1. **A follow-up needs a token too.** The `task` security scheme says the token is "minted when
   the hub spawned the task … refused after `done`/`failed`". A follow-up (`cloud_send`, B-05)
   revives a `done` task, and its worker must report again, but its first token is spent. The hub
   mints a new token for each follow-up and sends it in the follow-up text (earlier tokens of a
   live task keep working until they expire or the task finishes). Say so in the scheme's
   description: "one token per spawn and per follow-up".
2. **A stop spends the token as well.** The runner cannot stop a cloud session, so after the owner
   stops a cloud task its worker may still call `/session/report`. The hub treats `stopped` like
   `done`/`failed` (the token is refused). Add `stopped` to "refused after `done`/`failed`".
