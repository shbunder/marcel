# Contract request — S-03.3 (state watcher and `/events`)

Nothing in `contracts/` was changed. The runner follows item 1's proposed wording today.

1. **The fresh view on connect only when the client cannot resume** (`runner-api.yaml`, `/events`).
   The contract says: "On connect the runner first sends one `session.state` per known session". The
   story's done-when says: "A reconnect with `Last-Event-ID` gets no duplicates and misses nothing."
   Both cannot hold: on a resume the fresh view repeats states the client already has. The runner
   sends the fresh view only when it cannot resume (no id, an id older than the 1000 kept, an id from
   before a runner restart, or one it cannot read); a resumable id gets exactly the events after it.
   Proposed wording: "On a connect without a `Last-Event-ID` the runner can resume from, it first
   sends one `session.state` per known session, all carrying the newest `seq`, so a reconnecting hub
   can always rebuild its view. With a resumable id it sends exactly the events after it."
2. **Event ids survive a runner restart** (same place). Ids start at the runner's start time in
   milliseconds, so an id from before a restart is always older than every id of the new run and is
   answered with the fresh view. Worth one sentence in the contract, so the hub never assumes ids
   start at 1.
3. **For the hub lane (S-04.5), not a contract change:** `RunnerWatch` marks NUC tasks `unknown` when it
   cannot open the stream, then reconnects with its last id. If the runner process stayed up (the
   socket was unreachable for another reason), that id is resumable and no fresh view comes, so a task
   whose session did not change meanwhile stays `unknown`. Proposed: after marking tasks `unknown`,
   reconnect without `Last-Event-ID` (or re-read `GET /sessions`).
4. **For the hub lane:** a `runner.warning` raises the `runner_warning` alert, and the runner sends no
   event when it can see the sessions again (it only logs it). If the hub wants to clear that alert,
   the contract needs a way to say "resolved" (e.g. a `runner.recovered` event type).
