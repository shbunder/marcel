# Contract request — S-03.4 (transcript tailing, `GET /sessions/{id}/tail`)

The contract is not wrong; it is silent on three things the runner had to decide. S-03.4 ships with
the choices below. Please write them into `contracts/runner-api.yaml` (`tailSession`), or say
otherwise and the runner follows.

1. **A second tail for the same file replaces the first.** The older stream ends. "Same file" is the
   same session and the same `subagent` (or none). Refusing the second tail would break the hub: it
   reconnects as soon as its old connection drops, usually before the runner has noticed, and it
   gives up on any non-200 answer (`StreamRefused` in `hub/src/marcel_hub/runner_client.py`).
   Suggested wording: "One tail per file: a new tail of the same file ends the older one."
2. **400 `bad_request`** for an `offset` that is not a whole number of bytes, or a `subagent` that is
   not hex. The contract lists only 200 and 404. Suggested: add
   `'400': '`bad_request`: `offset` is not a whole number, or `subagent` is not an agent id.'`
3. **What happens when the file starts over.** An offset past the end of the file, or a file that is
   truncated or replaced while tailed, is streamed again from byte 0. Offsets then go backwards.
   The hub's `TailPosition.is_new` drops every event whose offset is at or below the one it stored,
   so a rewritten transcript's events are lost to the hub until they pass the old offset. Claude
   Code is not known to rewrite a transcript in place (a fork or copy starts a new file, SP2), so
   this is an edge case. Suggested: say so in the contract, and let the hub reset its position when
   the first event after a reconnect has an offset below the one it resumed from.

The runner also streams `subagent=` tails from `<session-id>/subagents/agent-<agent_id>.jsonl`, as
SP2 recorded; no contract change is needed for that.
