# Contract request — S-03.7 (usage probe)

Nothing blocks the story. One rule in `getUsage` needs a sharper wording.

## When a reading is stale

**What.** `contracts/runner-api.yaml`, `getUsage`, says: "When no reading is fresh (older than 15
minutes), `stale` is true and the last values are kept." That makes a reading taken 5 minutes ago
look fresh even when the latest attempt to read usage just failed (claude missing, an error, a
timeout, or `/usage` wording the runner cannot parse). The story's "done when" asks that "source
unavailable" returns `stale: true` straight away.

**What the runner does today.** `stale` is true when the last good reading is older than 15 minutes
**or** the latest attempt failed. The last values are kept in both cases. Before any good reading,
the answer is still 503 `no_reading`.

**Proposed change.** Replace the sentence in `getUsage.description` with:

> `stale` is true when the last good reading is older than 15 minutes, or when the latest attempt
> to read usage failed. The last values are kept in both cases.

And on `UsageReading.stale`, add `description: True when the last good reading is older than 15
minutes, or the latest attempt to read usage failed.`

No field or status code changes, so no version bump and no other lane is affected: the hub reads
`stale` the same way.
