# Contract request — S-03.2 (spawn, list, get, stop)

Nothing blocks the story. The runner answers a few errors that `contracts/runner-api.yaml` does not
list yet. Each one uses the existing `Error` shape, so the hub reads them like any other error.

## Status codes the runner answers that are not listed

| Operation | Status | `code` | When |
|---|---|---|---|
| `spawnSession` | 400 | `bad_request` | The body does not match `SpawnRequest`, `cwd` is not an absolute path to an existing folder, or `name`/`model` starts with `-` (claude could read it as a flag). `resumeSession` already lists this code. |
| `spawnSession` | 501 | `not_supported` | A `repo` spawn, until S-03.5 (worktrees) lands. |
| `listSessions`, `getSession`, `stopSession` | 503 | `roster_unavailable` | `claude agents --json` fails, so the runner cannot see any session. |
| `stopSession` | 502 | `stop_failed` | `claude stop` exits non-zero; `detail` holds what it said. |

## One rule that is stricter than the schema

`SpawnRequest.name` allows a leading `-` (`^[A-Za-z0-9._-]{1,60}$`). The runner refuses it.

**Proposed change.** List the four rows above on their operations, and change the `name` pattern
(on `SpawnRequest` and `ForkRequest`) to `^[A-Za-z0-9._][A-Za-z0-9._-]{0,59}$`. No field changes;
a patch version bump is enough. The hub (S-04.x) only needs to treat these as ordinary errors.
