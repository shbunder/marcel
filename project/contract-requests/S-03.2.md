# Contract request — S-03.2 (spawn, list, get, stop)

Nothing blocks the story. The runner answers a few errors that `contracts/runner-api.yaml` does not
list yet. Each one uses the existing `Error` shape, so the hub reads them like any other error.

## Status codes the runner answers that are not listed

| Operation | Status | `code` | When |
|---|---|---|---|
| `spawnSession` | 400 | `bad_request` | The body does not match `SpawnRequest`, `cwd` is not an absolute path to an existing folder, or `name`/`model` starts with `-` (claude could read it as a flag). `resumeSession` already lists this code. |
| `spawnSession` | 501 | `not_supported` | A `repo` spawn. **Until S-03.5** (worktrees) lands; then it goes away. |
| `spawnSession`, `listSessions`, `getSession`, `stopSession` | 503 | `claude_timeout` | `claude` did not answer in time. On a spawn the session may have started; the runner then records and stops it, and the message says whether the stop worked. |
| `spawnSession`, `listSessions`, `getSession`, `stopSession` | 503 | `claude_unavailable` | The runner could not run `claude` at all (missing, not executable). |
| `listSessions`, `getSession`, `stopSession` | 503 | `roster_unavailable` | `claude agents --json` fails, so the runner cannot see any session. |
| `stopSession` | 502 | `stop_failed` | `claude stop` exits non-zero; `detail` holds what it said. |

## Two rules that are stricter than the schema

- `SpawnRequest.name` allows a leading `-` (`^[A-Za-z0-9._-]{1,60}$`). The runner refuses it, so
  claude can never read a name as a flag.
- `SpawnRequest.model` is any string. The runner only accepts `^[A-Za-z0-9._\[\]-]{1,80}$`, not
  starting with `-` (`opus`, `sonnet`, `claude-sonnet-5-5`, `opus[1m]`).

**Proposed change.** List the rows above on their operations. Change the `name` pattern (on
`SpawnRequest` and `ForkRequest`) to `^[A-Za-z0-9._][A-Za-z0-9._-]{0,59}$`, and give `model` (on
`SpawnRequest` and `ForkRequest`) the pattern `^[A-Za-z0-9._\[\]][A-Za-z0-9._\[\]-]{0,79}$`. No field changes;
a patch version bump is enough. The hub (S-04.x) only needs to treat these as ordinary errors.
