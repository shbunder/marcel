# Contract request from S-04.14 — name the other ways a `report(note)` can be refused

**From:** S-04.14 (hub catch-up with contract 0.6). Not blocking: the hub ships with the codes below.

## What the contract says

`channel.schema.json` `CallAck.error` and session-api.yaml `Report` name one refusal for a note:
`too_many_notes` (the 11th note of a task).

## What else happens

A note can also fail for reasons that are not the worker's fault, and the hub answers each with a
`call_ack` error (nothing stored, not re-sent), with a message that ends "Put the fact in your
done summary instead.":

| Code | When |
|---|---|
| `notes_full` | the project's notes file would pass 1 MB (the memory file cap) |
| `memory_unavailable` | the hub has no memory folder, git failed, or the task's project has no usable notes file |

## Ask

1. Name `notes_full` and `memory_unavailable` next to `too_many_notes` in `CallAck.error` and in
   session-api.yaml `Report` (409 / 503 for the cloud path), so S-05.7 (the plugin's `note`) and
   S-07.x (cloud workers) can tell the worker what to do.
2. Say what a note longer than 1000 characters gets on the channel. Today it fails the schema, so
   the hub drops it as a bad frame and sends **no** `call_ack`; the channel server must check the
   length itself before sending, or the tool call waits. A `call_ack` error `bad_note` would let
   the hub answer it instead.
