# Contract request — S-04.3 (conversation store and app WebSocket)

Nothing blocks the story. These are gaps where the hub had to pick a behaviour.

## 1. Error codes the conversation routes use

**What.** The contract lists 400/404 responses but no codes for them.

**What the hub uses.** `conversation_not_found` and `message_not_found` (404), `bad_cursor` (400, a
`cursor` that is not from this conversation), `already_main` (400, `send-to-main` called on the
main conversation itself).

**Proposed change.** List them under `Error.code` next to the S-04.2 codes.

## 2. `GET /conversations` for an agent you do not own

**What.** The route lists only 200 and 401.

**What the hub does today.** An unknown agent, or another user's, gives an empty list, so the
answer does not reveal whether the agent exists.

**Proposed change.** None needed if that is the intent; otherwise add a 404.

## 3. `reply_count` on the main conversation

**What.** `Conversation.reply_count` is optional and its meaning is only clear for side threads.

**What the hub does today.** Side threads always carry it (0 when empty); the main conversation
leaves it out. `last_message_at` is present whenever the conversation has a message.

## 4. A `since` that is not a number

**What.** `/ws` says `since` is an integer ≥ 0 but not what happens otherwise.

**What the hub does today.** It sends `resync.required` (as for a `since` the hub never sent)
instead of refusing the socket, because a refused socket reads as "unpaired" on the phone.

**Proposed change.** Say so in the `/ws` description.

## 5. Who creates an agent's main conversation (S-04.2 request #2)

**What the hub has now.** `conversations.ensure_main_conversation(session, agent)` makes it and
sets `agent.main_conversation_id`. Nothing calls it yet; the agent-creation story should.
