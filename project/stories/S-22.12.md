# S-22.12 — The app picks a buddy

Against the mock hub at app-api 0.8.0 (S-02.15). B-49: each phone shows one buddy; switching is easy.

do:
1. Regenerate `MarcelAPI` from `contracts/app-api.yaml` (never hand-edit it). Remove the people screens
   (`PeopleModel.swift`, `PeopleView.swift`) and every `role` check.
2. **Switch:** tap the avatar in the chat header → a sheet with every live buddy (its avatar, name, and the last
   message of its main conversation from `GET /conversations/{id}/messages?limit=1`) and "New buddy". Picking one
   sends `PATCH /devices/{id}`. The current buddy lives in one place, new `MarcelKit/CurrentBuddy.swift` (an
   observable set from `Device.agent_id`), and every tab (chat, quests, map, items, notebook) reads its agent id from
   there instead of from `/me`'s first agent; those packages change only where they read it. A long-press on the avatar switches straight to the previous buddy.
3. **Settings › Buddies** replaces People: rename, look (the existing look picker, S-19.4), archive (with "Its chat
   and notebook stay readable"), and "Pair another phone" (`POST /pairing-codes`, shows the QR, optional "start on
   this buddy").
4. Pairing reads the optional `&buddy=` in the QR link (`Pairing.swift`).
5. Notifications for another buddy than the one shown open the app on that buddy (`ios/Marcel/App/`).

- [ ] `make ios-check` passes; new tests: the switch sends the PATCH and reloads the chat for the new buddy; a pairing

- [ ] Simulator screenshots against the mock hub (switch sheet, Settings › Buddies) in the commit; the owner signs off
