# S-04.4 — Task registry and state machine

do:
1. Implement the task CRUD and the state machine from `contracts/task-states.md`.
2. Illegal transitions raise an error and are logged.
3. Write `task_event` rows for every runner state event and transcript event.
4. A queue holds tasks that hit `cap_reached` and starts them in FIFO order when capacity frees up.
5. `POST /api/tasks/{id}/archive`: sets `archived_at` on a `done`, `failed` or `stopped` task (409
   otherwise); `GET /api/tasks?archived=true` lists them, and the default list hides them (B-17).
6. The task routes `POST /api/tasks/{id}/messages` (steer), `/stop` and `/handback`, per the contract:
   - steer records a `note` event (`author: user`) and hands the text to an `Outbox` interface that
     S-04.6 delivers over the channel; `queued`/`starting` tasks keep it until their session is up,
     a `done` task goes back to `working`, `stopped`/`failed` answer 409 `task_finished`;
   - stop asks the runner (through the S-04.5 client interface; a fake here) and moves the task to
     `stopped`, or removes it from the queue;
   - hand-back records a `note` (`handback: true`) and puts a system event for the brain in the Outbox.
done when:
- [ ] A table test covers every allowed and forbidden transition.
- [ ] Queue test: a cap of 1 with 3 spawns gives 1 working and 2 queued; stopping one starts the next.
- [ ] Archive test: a working task answers 409; an archived done task leaves the default list.
- [ ] Route tests: steer on a stopped task → 409 `task_finished`; steer on a done task → `working` and a
  `note` event; stop on a queued task removes it from the queue; hand-back reaches the brain's Outbox.
