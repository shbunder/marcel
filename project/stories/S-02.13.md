# S-02.13 — Contract: one person, buddies on phones, push through the relay

Lead only. **Step 0: stop if ADR-013 is not Accepted.** app-api 0.7.3 → **0.8.0** (breaking: routes removed). Read
first: `project/decisions/ADR-013-install-anywhere.md` § One person, many buddies; `plan/05-install-anywhere.md` § 2.

do:
1. **One person.** Remove `/users`, `/users/{user_id}`, `/users/{user_id}/pairing-codes`, the `people` tag,
   `UserRole`, `x-owner-only` and its explanation in the `info.description`. `Me` keeps `user_id` and `name`, drops
   `role`. Every route is open to any paired device of the one user.
2. **Buddies.** An agent is called a buddy in descriptions (the schema name `Agent` stays, so clients do not churn).
   Add `POST /agents` (name, optional look `{animal, palette, personality}`; the hub picks the look from the name when
   none is given; returns `Agent`) and `POST /agents/{agent_id}/archive` (a buddy's brain stops; its chat and memory
   stay readable; 409 for the last live buddy).
3. **A phone's buddy.** `Device.agent_id` (the buddy this phone shows; required in responses) and
   `PATCH /devices/{device_id}` `{agent_id}` (404 for an unknown or archived buddy). Pairing: `POST /pairing-codes`
   (any paired device; optional `agent_id` the new phone starts on) returns `{code, link, expires_at}`; the
   `PairingCode` link format stays `marcel://pair?hub=…&code=…`, plus an optional `&buddy=<agent_id>`.
4. **Relay push.** `PushTarget` gains a third kind, `relay`: `{kind: relay, relay_url, handle, send_secret,
   device_key}` where `device_key` is the phone's X25519 public key (base64url, 32 bytes). `Me.push` gains
   `relay: bool` (and `kind: none` after the hub cleared a target the relay said is gone, so the phone registers
   again). Describe the sealed payload in a new component `SealedPush`: `{v: 1, eph, nonce, box}` —
   X25519 (hub's ephemeral key with `device_key`) → HKDF-SHA256 (salt = `eph ‖ device_key`, 64 bytes; info
   `marcel-push-v1`; 32-byte output) → ChaCha20-Poly1305 (12-byte random `nonce`; associated data the ASCII bytes
   `marcel-push-v1`; `box` = ciphertext followed by the 16-byte tag) over the UTF-8 JSON `{title, body, link,
   agent_id}`. All three fields base64url without padding. The relay never gets the key.
5. **The relay's own API**, new `contracts/push-relay.yaml` (OpenAPI 3.1): `POST /v1/register` (from the app:
   `{apns_token, sandbox}` → `{handle, send_secret}`; `handle` 22 random base64url chars), `POST /v1/push` (from a
   hub: header `Authorization: Bearer <send_secret>`, body `{handle, sealed: SealedPush, urgent: bool}`; 202, 401,
   410 when APNs says the token is gone, 413 over 3 KB, 429 over 500 a day per handle), `DELETE /v1/handles/{handle}`
   (same bearer). The relay stores only `handle → apns_token, sha256(send_secret), sandbox, day count`.
6. **The computer's kind.** `Health.os` (`macos | linux`), so the app can say "Your Mac is asleep" (S-22.17).
7. **Events.** `events.schema.json`: `device.updated` carries the new `agent_id`; a `user.*` event, if any, goes.
8. **Keep `main` green.** `hub/tests/test_contract_routes.py` and the mock hub's route test: the removed routes go in a
   `RETIRED` list (still served until S-22.11 / S-02.15 remove them) and the new ones in `PENDING_*`, each naming the
   story that serves it. `hub/tests/test_contract.py`: retire the `UserRole` mapping and put `Device.agent_id`, the
   `relay` push kind and `Health.os` in `PENDING`, each naming the story that serves it (S-22.11, S-22.15, S-22.27).
   `contracts/tests/test_contract_0_7.py`: the assertions that `/users`, `x-owner-only` and `UserRole` exist are
   retired (0.8.0 removes them on purpose).
9. Contract tests (`contracts/tests/test_contract_s02_13.py`): the removed routes are gone; `POST /agents` and the
   device's buddy validate with examples; a `SealedPush` example decrypts with a fixed test key in the test (Python
   `cryptography`, added as a dev dependency in `contracts/pyproject.toml`), so the hub and the app have one known-answer vector to test against.
10. `contracts/README.md`: the 0.8.0 change list. Answer any open `project/contract-requests/` this covers.
11. **No pin on a Mac** (runner-api 0.1.13 → 0.1.14; ADR-013 question 5 as amended after SP11; S-22.6 builds it).
   In `contracts/runner-api.yaml`: `claude_change.required: [from, to, expected]` becomes `[from, to]`, and its
   description says `expected` is absent on an install that follows the user's Claude Code; `Health.claude_version_expected`
   (already optional) says absent means no pin, and then a different `claude_version` never makes `ok` false; the four
   422 `claude_version` descriptions (spawn, resume, fork, cloud start) say "only when a pin is set". Additive for the
   hub: a pinned runner sends exactly what it sends today. The runner-api row in `contracts/README.md` names 0.1.14.
12. **Lead items folded in (2026-10-15).** (a) Trackers, from S-20.2: `Project.tracker_url` and channel
    `Artifact.role: tracker` accept only `https://claude.ai/artifact/<id>` or `https://claude.ai/code/artifact/<id>`,
    and only the project's kickoff quest sets or replaces it: brain-api 0.1.4 → 0.1.5 `NewTask.kickoff` (needs
    `project`). The hub and plugin enforce it in S-20.3. (b) runner-api `Error.detail` says what it holds for
    `GET /usage` 503 (the cause in plain words); wording only (the runner-api bump is step 11's).
13. A buddy's look is `NewLook` (`{animal, color, personality}`, as `AgentUpdate.look`); "palette" in step 2 means
    its `color`.
