# S-03.2 — Spawn, list, get, stop

do:
1. `spawn` builds the command line `claude --bg --name <name> --model <model> --permission-mode <mode>
   --channels plugin:marcel@marcel-local --debug-file <path> -- "<prompt>"` in the task's cwd, with a
   scrubbed environment (no inherited `CLAUDE*` variables) and `claude` called by absolute path. It parses
   `backgrounded · <short-id> · <name>`, resolves the full id from `agents --json`, and fails the spawn
   with a readable reason if the debug log says the channel was `skipped` or the workspace is not trusted.
2. It returns the session id. `list` and `get` come from `claude agents --json --all`, normalised.
   If the session is connected to Remote Control, `get` also returns its claude.ai URL as
   `remote_url` (where it can be read from is part of SP1/SP2's answer; if nowhere, it stays absent).
   `stop` calls `claude stop`.
3. Enforce the **concurrency cap**: when the cap is reached, `spawn` returns `409 cap_reached`. Brain and side
   sessions do not count toward the cap.
done when:
- [ ] Each command line is asserted exactly against a golden file.
- [ ] Cap test: with the cap at 2, the third spawn fails, and it passes again after a stop. Removing the cap check makes this test fail.
- [ ] A session that the shim reports as `failed` is reported as failed, with the shim's reason.
