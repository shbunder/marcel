# SP13 — Buddies message each other with Claude Code's own messages

For ADR-013 ("One person, many buddies"). Claude Code's cross-session messages (`SendMessage`, `ListAgents`; same
machine over a local socket; docs: https://code.claude.com/docs/en/cross-session-messaging) instead of Marcel's own.

**Steps** (two background sessions `--name pip` and `--name marcel`, each with the marcel plugin, as the brain
settings will be; a third, a worker with `runner/src/marcel_runner/role_settings/worker.json`):
1. With `crossSessionInbound: accept` on both brains: `marcel` sends to `@pip`; does `pip` get a new turn with no
   terminal attached? What does the transcript record (role, text, sender)?
2. Add `SendMessage` and `ListAgents` to the worker's `permissions.deny`: the worker cannot send to a brain (record the
   error). Without the deny, it can — so the deny is the control. Also a side thread (a fork of a brain, started with
   `--settings` holding `crossSessionInbound: refuse` and the same deny): does its `--settings` beat the brain folder's
   project `accept`?
3. A plugin `PostToolUse` hook with matcher `SendMessage` on the sender: does it fire, and does its input carry the
   target name and the text?
4. Is a brain's `--name` stable across `claude respawn` and `--resume`, so a buddy can always be addressed by its
   slug?
5. Send 20 messages back and forth: note the rate limit or drop behaviour the docs mention.

**Pass:** 1–4 work → S-22.13 uses them. **Fallback:** buddy messages go through the hub (a `buddy_message` brain tool
that the hub delivers through the channel), recorded in ADR-013.
