# S-02.2 — Runner API, transcript schema, channel protocol

do:
1. Specify the runner API: JSON over HTTP on a unix socket.
   - Operations: `spawn{role,model,cwd|repo,prompt,permission_mode,env}`, `list`, `get`, `send`, `stop`, `fork`,
     `tail` (Server-Sent Events, resumable by offset), `cloud_spawn`, `cloud_send`, `usage`, `health`.
   - Event stream: `GET /events` (SSE) for state changes.
2. Specify the normalised transcript event schema (from SP2's fixtures): `text`, `tool_call`,
   `tool_result`, `diff`, `permission`, `subagent_start/stop`, `error`, `state`.
3. Specify the channel protocol between the plugin channel server and the hub's `/channel` WS:
   - hello (role, agent_id, conversation_id | task_id, session_id);
   - inbound `user_message` / `steer` / `system_event`;
   - outbound `reply` / `report{progress|artifact|done|failed}` / `permission_request` /
     `permission_result`;
   - heartbeat;
   - auth with a per-session token minted by the hub.
4. Specify the session endpoints in `contracts/session-api.yaml` (OpenAPI 3.1), under the same
   `/api` server as the app API: `POST /api/session/adopt` (S-05.4, adopt token) and
   `POST /api/session/report` (S-07.2, task-scoped token; the same payloads as the channel's
   `report`).
done when:
- [ ] The schemas validate, and SP2 fixtures convert to transcript events in a contract test.

## From the spikes (2026-10-04)

- Channel hello = `{session_id: $CLAUDE_CODE_SESSION_ID, …}`; no role or task id from env (SP1, SP7). The hub answers with the role and conversation or task, or rejects an unknown session id.
- Permission requests use Claude Code's own shapes: `notifications/claude/channel/permission_request {request_id, tool_name, description, input_preview}` and the answer `{request_id, behavior: allow|deny}`; request ids are 5 lowercase letters (SP1).
- Transcript schema: use the mapping table in SP2's RESULT.md (`text`, `tool_call`, `tool_result`, `diff` from `structuredPatch`, `subagent_start/stop`, `raw`). A pending `permission` is not in the JSONL: it comes from the runner's state stream (`blocked` + `waitingFor: "permission prompt"`, text from `jobs/<id>/state.json` `needs`).
- Runner API: `spawn` returns the session id; `tail` resumes by byte offset (SSE `id:`); `usage` returns the parsed `/usage` reading (SP4); `cloud_spawn` returns id and URL (SP3).
- Session API: the report endpoint must 404 anything without a valid per-task token; scanners probed the tunnel within minutes (SP3).
