# S-22.14 — The push relay

The one service the owner runs for every install (ADR-013 question 2): a Cloudflare Worker that holds the APNs key.
API: `contracts/push-relay.yaml` (S-02.13). New lane `relay/` (TypeScript, the toolchain the channel server uses).

do:
1. `relay/`: a Worker (`wrangler`), storage in one D1 table (not KV: the daily count must be atomic) (`handle → apns_token, sha256(send_secret),
   sandbox, day, count`). `POST /v1/register`, `POST /v1/push`, `DELETE /v1/handles/{handle}` exactly as the
   contract says.
2. APNs with token auth (ES256 JWT, cached under 60 minutes) from Worker secrets `APNS_KEY`, `APNS_KEY_ID`,
   `APNS_TEAM_ID`, `APNS_TOPIC`. The push is `{aps: {alert: {title: "Marcel", body: "You have news"},
   "mutable-content": 1}, sealed: <SealedPush>}`; `urgent` sets `interruption-level: time-sensitive`. APNs 410 →
   the handle is deleted and the relay answers 410.
3. **What it never does:** log or store a request body; decrypt anything (it has no key); accept a push for a handle
   without that handle's secret. Rate limit 500 a day per handle, 413 over 3 KB.
4. `relay/README.md`: what the relay sees (the table from `plan/05-install-anywhere.md` § 2), the owner's one-time
   deploy (`npm ci`, `wrangler login`, `wrangler secret put …`, `wrangler deploy`) and the address to put in the app
   build (`MARCEL_RELAY_URL` in `ios/Config`, S-22.16).
5. `npm run check` (types, lint, vitest with Miniflare) in `relay/`; add `relay` to the root `make check` and a `relay` job to `.github/workflows/check.yml`.
done when:
- [ ] Vitest: register → push → APNs called once with the sealed bytes untouched (a fake APNs); a wrong secret → 401
      and no APNs call (removing the secret check fails it); 501st push in a day → 429; APNs 410 → handle gone.
- [ ] A test asserts no `console.log` of a request body (grep in the test over `relay/src`).
