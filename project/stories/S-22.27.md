# S-22.27 — The hub's buddy routes, and pushes follow the phone's buddy

app-api 0.8.0 (S-02.13), after S-22.11 removed the people model.

do:
1. `POST /agents` (a new agent with its main conversation and Inbox; the brain keeper starts its brain as for any
   agent, S-17.7; look from the name when none is given, as `POST /users` did) and `POST /agents/{id}/archive` (409 for
   the last live buddy). `marcel-hub setup` makes the first buddy as today.
2. `PATCH /devices/{id}` `{agent_id}` (sends `device.updated`); `POST /pairing-codes` with optional `agent_id`, whose
   link adds `&buddy=`; `marcel-hub pair --buddy <slug>`.
3. **Pushes:** a buddy's notices go to the phones showing that buddy; notices with no buddy (redeploy, backup, usage,
   logged out, self-change) go to every phone (`notify/routing.py`, `notify/pusher.py`).
4. `/health` returns `os` (`macos` or `linux`, from `platform.system()`).
5. **Memory per buddy** (app-api 0.8.1): `GET /memory` and `GET`/`PUT /memory/files/{path}` read an optional
   `agent_id` query parameter (`memory.py` `_repo`). Omitted: the calling phone's buddy (`Device.agent_id`), not the
   person's first agent. An id that is no buddy → 404 `agent_not_found` on all three; an archived buddy's memory reads
   as usual, and a `PUT` to it → 404 `agent_not_found`. Drop the three `PENDING_QUERY_PARAMETERS` entries in
   `test_contract_routes.py`.
6. Drop the `PENDING_OPERATIONS` entries S-02.13 put in `test_contract_routes.py` for these routes, and send `archived_at` in `agent_json` (the `Agent` row has the column already). (`Health.os` has no stored model, so it has no `PENDING` entry: the `/health` test above is its check.)
done when:
- [ ] Tests: `/health` carries `os`; archiving the last buddy → 409; switching a phone's buddy moves that buddy's next push to it and away from
      the others; a Marcel-wide notice reaches every phone; a pairing code with `agent_id` pairs a phone showing it; `GET /memory?agent_id=` of a second buddy lists that
      buddy's files, and without it the phone's buddy's; an unknown `agent_id` → 404 `agent_not_found`; a `PUT` to an
      archived buddy → 404 and nothing is committed.
