# S-22.3 — The runner on macOS

The runner was built for Linux: it proves Claude's supervisor runs outside its own service by reading
`/proc/<pid>/cgroup` (`runner/src/marcel_runner/health.py:54`, `cgroup_of`). macOS has no `/proc`. Read first:
`scratch/spikes/SP11-mac-services/RESULT.md` step 2 (how a LaunchAgent job is told apart).

do:
1. New `runner/src/marcel_runner/platform.py`: `own_service_check(pid)` with a Linux version (today's cgroup compare,
   moved) and a macOS version (from SP11, e.g. the supervisor's pid is the pid of the `com.marcel.claude-daemon`
   LaunchAgent (the label S-22.4's service table fixes; until then SP11's label) in `launchctl print gui/<uid>/…`, and not a descendant of the runner). `health.py` and `sessions.py`
   call it; the answer keeps the same `supervisor {running, own_unit}` shape (no contract change).
2. Any other Linux-only call on the runner's paths (`/proc`, `/run/user`, GNU tools) gets a macOS path or a plain
   "not on macOS" error. Grep `runner/src` for `/proc` and `/run/`.
3. The fake `claude` shim and tests run on both systems; the macOS check is tested with a fake `launchctl`.
4. `docs/runner.md`: what the runner checks on each system.
done when:
- [ ] Unit tests: on a fake macOS, a supervisor started by the runner itself is refused with the same plain message as
      on Linux; removing the check makes a test fail (inert-controls rule).
- [ ] On the Mac, with SP11's LaunchAgent: `curl --unix-socket ~/marcel/run/runner.sock http://runner/health` says
      `"own_unit": true`, and `make -C runner test-live` passes (pasted in the commit message).
