# S-22.3 — The runner on macOS

The runner was built for Linux: it proves Claude's supervisor runs outside its own service by reading
`/proc/<pid>/cgroup` (`runner/src/marcel_runner/health.py:54`, `cgroup_of`). macOS has no `/proc`. Read first:
`scratch/spikes/SP11-mac-services/RESULT.md` steps 2 and 4: on a Mac Marcel runs no `claude-daemon` job of its own;
Claude's supervisor starts on demand from the runner's first `claude --bg` (Claude Code has turned its service install
off), it is shared with the user's own sessions, and the user's newer `claude` may replace it at any time.

do:
1. New `runner/src/marcel_runner/platform.py`: `own_service_check(pid)` with a Linux version (today's cgroup compare,
   moved) and a macOS version. On a Mac `own_unit` means **the supervisor outlives a restart of the runner's
   LaunchAgent** (`launchctl kickstart -k`). SP11 step 2 measures what tells that apart (the supervisor's pid,
   process group and session against the runner job's, from `ps -o pid,ppid,pgid,sess`, and `claude daemon status`,
   which prints its pid, version and `origin`); build the check from that record, not from a guess. If the record shows
   the on-demand supervisor sits in the runner job's process group, the fix is in S-22.4's runner plist
   (`AbandonProcessGroup`), and this check tests that the plist has it. The answer keeps the same
   `supervisor {running, own_unit}` shape (no contract change). Mac wording for a refusal: "Claude's background
   supervisor would stop when Marcel's runner restarts, which would end every session. Restart the runner with
   `marcel start runner`." (today's message names `marcel-claude-daemon.service` and `systemctl`: `health.py` and
   `watch.py`).
2. **No supervisor is not an error on a Mac.** The next `claude --bg` starts one. So on macOS `collect_health` keeps
   `ok` true with `supervisor.running: false`, the start-up gate (`server.py`, which raises `StartupError` unless the
   supervisor is running in its own unit) and the spawn gate (`sessions.refuse_start`, 422 `no_supervisor`) let it
   through, and both still refuse a running supervisor that would not outlive the runner.
3. **Never stop the shared supervisor.** On a Mac the runner never runs `claude daemon stop`; it stops only its own
   sessions (`claude stop <id>`). Other people's background sessions (the user's own) may be on the same supervisor.
4. Any other Linux-only call on the runner's paths (`/proc`, `/run/user`, GNU tools) gets a macOS path or a plain
   "not on macOS" error. Grep `runner/src` for `/proc` and `/run/`. The socket's default on macOS is
   `$MARCEL_HOME/run/runner.sock` (`server.py` defaults to `$XDG_RUNTIME_DIR` or `/run/user/<uid>` today), as S-22.1
   does for the hub.
5. The fake `claude` shim and tests run on both systems; the macOS check is tested with a fake `ps` and a fake
   `claude daemon status`.
6. `docs/runner.md`: what the runner checks on each system, and that a Mac shares the supervisor with the user.

      leaves a running background session alive; and `make -C runner test-live` passes (pasted in the commit message).
