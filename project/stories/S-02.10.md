# S-02.10 — Contract: rollover reads, session-end edge cases, worker role settings, who wrote a message

Lead only. Writes down what the hub and the runner already do on main, from the contract requests
`project/contract-requests/S-06.8-rollover-reads.md`, the S-05.8 board log row `20261013T2232-S-05.8-contract-request`,
`project/contract-requests/S-03.10.md` and S-11.1 item 1, plus one optional field from S-19.3. No new routes; the one
new field goes on the hub's shrink-only `PENDING` list in `hub/tests/test_contract.py`.

do:
1. **Rollover reads (S-06.8, brain-api 0.1.4).** The `X-Marcel-Session` rule: a rollover's new brain that has not
   said hello yet may make `GET` requests on the read-before-hello routes, as its agent's main conversation; any
   other call answers 401 `unknown_session`. The check order gains that step before `unknown_session`. The routes
   are the hub's `brain_api.READ_BEFORE_HELLO`: `GET /tasks`, `/tasks/{task_id}`, `/projects`, `/memory`,
   `/schedules`, `/summary`, `/usage`. A hub test pins `READ_BEFORE_HELLO` to the contract's list.
2. **Session end (S-05.8, session-api 0.1.7, task-states.md).** `sessionEnded`: a worker whose task is `silent`
   also fails with `ended_without_report` when its session ends, though its `report_owed` is false (task-states.md
   already allowed it; session-api now agrees). When the task already ended, or the session is a brain, side or
   adopted one, the end reason is only written to the hub's log: no task event.
3. **Role settings on resume (S-03.10, runner-api 0.1.11).** A worker's spawn passes `--settings` with the runner's
   `role_settings/worker.json`; resume's 422 `exited` also covers saved options that lack the role's `--settings`.
4. **Who wrote a message (S-19.3, app-api 0.7.2).** Optional `Message.agent_id`: on an `agent` message, the agent
   that wrote it, so the app credits a reply without a quest to the right helper; absent on `user` and `system`
   messages. The hub does not fill it yet (a follow-up hub story), so `'Message': {'agent_id'}` is pending.
5. **Approving a self-change (S-11.1 item 1, app-api 0.7.2).** `Approval.artifact_id`: approving is the owner's
   go-ahead; the owner merges on GitHub (ADR-005) and only a PR both approved and merged is redeployed.
   iOS then needs `make -C ios generate` (a separate task).

Deferred, with one line each in their request files: S-05.4 (`elsewhere` and the adopt fields need app-api, iOS
and hub work), S-07.2 item 1 (`report_id` needs hub work first), S-11.1 items 2 and 3 (hub work first).
