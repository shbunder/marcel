# S-03.5 — Resume, fork, worktrees

do:
1. `resume` (runner-api.yaml `/sessions/{id}/resume`) continues a stopped session between turns. A
   live session is never sent text by the runner: that goes hub → channel (409 `running`).
2. `fork` creates a background fork of a session (SP7). Its role is `side`; it takes the recorded
   permission mode and model of the session it forks from.
3. `workspaces.ensure(repo)` clones into `~/marcel/workspaces/<repo>` once, accepts the trust prompt,
   and installs the marcel plugin there at **local** scope (`claude plugin install marcel@marcel-local
   --scope local`), so no tracked `.claude/settings.json` is written into someone else's repo. Then it
   creates a worktree per task on branch `marcel/<task-id>-<slug>`.
done when:
- [ ] Worktree create and cleanup tests run against a local bare repo.
- [ ] A fork test runs against the shim.
- [ ] Test: a fresh clone gets the plugin at local scope, and its tracked files are unchanged (`git status` is clean).
- [ ] Test: resume of a live session answers 409 `running`; a copy started by resume answers 409 `resume_copied`.

## From the spikes (2026-10-04)

- `send` to a live session goes through the channel only; there is no `claude send`. Between turns, `claude stop` then `claude --bg --resume <uuid> -- "<msg>"`, but wait until the id leaves `~/.claude/daemon/roster.json`, or a copy starts instead (parse the `note:` line and treat it as failed).
- `fork` = `claude --bg --resume <uuid> --fork-session --name <name> --channels plugin:marcel@marcel-local -- "<opening prompt>"`; it returns a new session id (SP7).
- `workspaces.ensure(repo)` accepts the trust prompt once per clone (worktrees inherit it); the dialog's default is "No, exit", so it must pick "Yes" explicitly (`scratch/spikes/SP2-worker-control/accept_trust.py`).
