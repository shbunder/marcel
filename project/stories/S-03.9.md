# S-03.9 — Runner catch-up with runner-api 0.1.7

Contract 0.6 answered the S-03.6 and S-06.2 requests (project/contract-requests/, now deleted).

do:
1. `POST /cloud/sessions` takes an optional `repo` (`CloudRepo {url, base?}`): make sure the workspace
   clone exists and is fetched (reuse the `repo` spawn's clone step), and run `claude --cloud` in a folder
   of that clone checked out at `base` (the default branch when absent). `clone_failed` (422) and
   `git_timeout` (503) as for a `repo` spawn. Without `repo`, nothing changes.
2. Both cloud operations answer `400 bad_request` for a bad body or session id, and `503 claude_timeout` /
   `claude_unavailable` instead of the `422` they use for those cases today.
3. `CloudSpawned.url` and `CloudAck.url` are always `https://claude.ai/code/<session id>` (already so;
   keep the test that proves it).
4. `turn_end` carries `usage` (transcript.schema.json `TurnEnd.usage`): the four token counts of the turn's
   last main-thread assistant line, cleared at each turn end; never from subagent lines. Port it from
   `contracts/tests/reference_normalizer.py` (`normalize_file(..., with_usage=True)`), and compare the
   runner with the reference **with** usage in `test_transcript.py`.
