# S-04.6 — Channel gateway

do:
1. Implement the `/channel` WS per `channel-protocol.md`. A connection proves itself with the shared hub
   secret, and is accepted only for a session id the runner reported at spawn or fork (or an adopted one).
   Answer every `reply` and `report` with `call_ack`, also for a repeated `call_id`.
2. Route each connection:
   - **brain or side** connections: deliver the conversation's user messages; store replies as agent messages;
   - **worker** connections: deliver steer messages; `report` becomes task events, artifacts and milestones;
     `permission_request` creates an `approval` plus a card plus a push; `POST /approvals/{id}` sends
     `permission_decision` back (a denial's note follows as a `steer`, or a `user_message` for brain and side).
3. Queue messages for a session that is not connected; deliver them on hello. This queue is the
   `Outbox` that S-04.4's steer and hand-back routes write to.
4. Resolve approvals answered elsewhere: when the runner's state stream shows the session left
   `waiting_for: permission prompt` without a `permission_decision` from the hub, read the transcript
   (`tool_result.denied`) and resolve the card `approved` or `denied` with `answered_via: terminal`.
   When a task stops or fails with an open approval, the approval becomes `expired`. Both send
   `approval.resolved`.
done when:
- [ ] Test: approve flow end to end with a fake channel client.
- [ ] Test: an approval answered in the terminal (the runner reports the session left the prompt, the
  transcript shows the tool ran) resolves the card `approved` with `answered_via: terminal`; with
  `denied: true` in the transcript, `denied`.
- [ ] Test: a repeated `call_id` is stored once and acked twice.
- [ ] Test: a message for an offline session is delivered after reconnect.
- [ ] Test: stopping a task with an open approval expires it; answering an expired approval → 409 with
  its current state.
