# S-17.7 — A brain per person

The hub runs in Docker and cannot render `brain/` or trust a folder (`brain/README.md` § After rendering), so this is
a host step through the runner.

do:
1. Runner `prepare_brain`: render `brain/` into `~/marcel/brains/<slug>` with the agent's name, link
   `MEMORY.md`/`memory/` to `agents/<slug>/` in the memory repo, and trust the folder. The owner's existing
   `~/marcel/brain` is re-linked to `agents/marcel/`.
2. Adding a person (`POST /users`) creates their agent (name, look from the name when none given), main conversation,
   Inbox, and calls `prepare_brain`. The brain keeper starts one brain per agent, each in its own folder.
3. Archived agents: no brain, no schedules, no digests.
4. Every brain and quest still runs on the owner's Claude login and shares the worker cap and the usage guard.
done when:
- [ ] Live on the NUC: add Emma → her brain starts in its own folder; a message to her brain never reaches Marcel's.
- [ ] Unit tests: archived agents are skipped by the keeper, the scheduler and the digest.
