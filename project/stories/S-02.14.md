# S-02.14 — Contract: more computers and the computer link

Lead only. app-api 0.8.0 → 0.9.0, session-api and brain-api minor, additive. Read first:
`plan/05-install-anywhere.md` § 6. The runner API (`contracts/runner-api.yaml`) does **not** change: the link
carries it.

do:
1. **Computers** (app-api): `Machine {id, name, os: macos|linux, online, last_seen_at, cap, running, is_hub}`;
   `GET /machines`, `POST /machines/join-codes` → `{code, command, expires_at}` (8 characters, 10 minutes, once, the
   same alphabet as pairing codes; `command` is the line to paste: `curl -fsSL … | bash -s join <code>`),
   `DELETE /machines/{id}` (the link is closed and its token revoked; 409 for the hub's own computer).
   `Task.machine_id` (nullable for cloud tasks). Events `machine.updated`.
2. **Joining** (session-api): `POST /api/machines/join` `{code, name, os}` → `{machine_id, machine_token}` (shown
   once; stored hashed). Same guess limit as `/pair`.
3. **The link**, new `contracts/machine-link.md` + `machine-link.schema.json`: the helper opens
   `wss://<public>/api/machines/link` (listed in `session-api.yaml` as a WebSocket upgrade, as `/ws` is in app-api) with `Authorization: Bearer <machine_token>`. Frames (JSON, one per WS message):
   - hub → helper `runner.request {id, method, path, body?}`; helper → hub `runner.response {id, status, body}`, and
     for streaming paths (`/events`, `/sessions/{id}/tail`) `runner.chunk {id, line}` … `runner.end {id}`; hub →
     helper `runner.cancel {id}`.
   - helper → hub `local.open {id, kind: channel|http, path, method?, headers?, body?}` for what sessions on that
     computer send to `127.0.0.1:7420` (the channel WebSocket and the plugin's HTTP calls), then `local.data`,
     `local.close`; the hub answers on the same id. `http` may only name `/channel/session-end` and `/brain/…`
     paths. The hub applies the same session checks as on its own computer:
     only session ids that this computer's runner started.
   - `ping`/`pong` every 20 s; a link silent for 60 s is down (`Machine.online` false).
4. **Where a quest runs** (brain-api): `tasks_spawn` gains optional `machine` (a computer's name). Unknown or offline
   → a plain error the brain can repeat ("Shaun's iMac is offline").
5. `PENDING_*` entries in `hub/tests/test_contract_routes.py` for every new route (S-22.19, S-22.20).
6. Contract tests and examples for every frame; `mock-hub/` serves `/machines` with two computers, one offline.
done when:
- [ ] `make -C contracts check`, `make -C mock-hub check` and `make -C hub check` pass.
- [ ] A schema test rejects a `runner.request` without `id` and a `local.open` with an unknown `kind`.
