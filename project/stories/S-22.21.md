# S-22.21 — marcel join — a helper on another computer

(`S-22.25` is in `depends:` only so that `deploy/cli/` is not changed by two stories at once.)

The user's second computer (Claude Code installed and logged in) runs only Claude's supervisor, the runner and the
link (ADR-013 question 6).

do:
1. `runner/src/marcel_runner/link.py` (adds the `websockets` dependency to the runner, its first): opens the link to
   the hub with the machine token, answers `runner.request` frames by calling the local runner socket, and serves a
   stand-in on `127.0.0.1:7420` that forwards `/channel` and plugin HTTP calls as `local.open` frames. Reconnects with
   backoff up to 60 s (sleep and Wi-Fi changes are normal).
2. `get.sh … | bash -s join <code>` → `marcel join <code>`: the same checks, toolchain, pinned Claude copy, channel
   drop-in and plugin (into `~/marcel/workspaces/scratch`) as `marcel install`, then `POST /api/machines/join`, the
   token in `~/.config/marcel/machine-token` (0600), and the services `claude-daemon`, `runner`, `link`. No hub, no
   tunnel, no brain. The helper writes a fresh random hub secret into the plugin's data folder (as `marcel install`
   does) and the stand-in checks it, as the hub's `/channel` does.
3. `marcel uninstall` on that computer also tells the hub (`DELETE` is the user's choice in the app; uninstall just
   closes the link and removes the token).
4. `docs/install.md` § Another computer.
done when:
- [ ] Unit tests with a fake hub: a `runner.request` is answered from a fake socket; a `/channel` connection to the
      stand-in becomes a `local.open` frame; a dropped link reconnects.
- [ ] Live: on a second Mac or the NUC, `marcel join <code>` → the computer shows online in `GET /machines`; a quest
      started there (`tasks_spawn(machine=)`, S-22.22) runs, streams its transcript and asks for an approval in the app.
