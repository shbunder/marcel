# S-20.2 — Project tracker for coding projects

A Jira-like overview of a coding project, readable on the phone and the laptop, built as a claude.ai artifact so Marcel
needs no new screen. The model is this repo's build board (`project/board.html`, collection `stories`, statuses
Backlog → In Progress → Review → Done). **If SP9 ends in its fallback, rewrite this story first.**

do:
1. A tracker template in the plugin (`templates/tracker/`), generalised from `project/board.html`: columns by status,
   cards with title, quest, PR link and CI state, a "waiting on you" lane; works at phone width.
2. The kickoff quest publishes one tracker per coding project and reports it as `report(artifact, kind=link,
   role=tracker)`; the hub sets `project.tracker_url`. The hub reads `role` (`ARTIFACT_FIELDS` in `channel/frames.py`;
   take it off `PENDING_ARTIFACT_FIELDS`). Only the channel carries `role`, so the kickoff quest runs on the NUC.
3. `worker-protocol`: a coding quest in a project with a tracker moves its own card (In Progress at start, Review with
   the PR link) and writes a log row. `digest`: the evening digest turn moves cards whose PR merged to Done.
done when:
- [ ] Hub test: a `role=tracker` artifact sets `tracker_url`; a second one replaces it.
- [ ] Scripted replay: kickoff → a tracker report; a quest's replay contains the card moves (In Progress, Review).
- [ ] The template has no fixed width over 400 px (a layout lint over its CSS) and renders without script errors in
      the plugin's existing test runner.
