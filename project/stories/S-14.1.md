# S-14.1 — Compose, systemd, tunnel

1. `deploy/docker-compose.yml`:
   - hub on 127.0.0.1:7420;
   - `/data` volume;
   - runner socket mounted;
   - `restart: unless-stopped`.
2. systemd user units:
   - `marcel-runner.service`;
   - `marcel-redeploy.path` and `marcel-redeploy.service`;

## From the spikes (2026-10-04)

- Install `/etc/claude-code/managed-settings.json` (root, once): `channelsEnabled: true`, `allowedChannelPlugins` = marcel@marcel-local plus telegram and imessage @claude-plugins-official (ADR-001).
- Register the `marcel-local` marketplace pointing at a deployed copy of `plugins/marcel/`, and install the plugin project-scoped in `~/marcel/brain` and in each worker workspace.
- Units: `marcel-claude-daemon.service` (`claude daemon run`, its own cgroup), `marcel-runner.service` (`Requires=` it; `RuntimeDirectory=marcel`, `RuntimeDirectoryPreserve=yes`, PATH with `~/.local/bin`), and `sudo loginctl enable-linger <user>`. Templates: `scratch/spikes/SP6-hub-runner-socket/`.
- Compose: the hub runs as `user: "${UID}:${GID}"`, mounts the runner directory (never the socket file) at `/run/marcel`, and mounts no `~/.claude`.
- After a Claude Code update, prefer `claude respawn --all` over restarting the supervisor unit, which stops every session.
- The hub image must contain `hub/migrations/`: `marcel_hub.db.MIGRATIONS_DIR` resolves it relative to the source tree (S-04.1).

## From the S-03.1 review

- The runner refuses to start while Claude's supervisor isn't up. `marcel-runner.service` comes up right after `marcel-claude-daemon.service`, so give it `Restart=on-failure` with `RestartSec=5` and a start limit that tolerates a slow supervisor start. Drill it: start both units cold, and the runner is healthy within 30 s.

## From the S-05.1 review

## From the NUC, 2026-10-04

- `marcel-claude-daemon.service` is not installed or not active on the NUC today (`inactive`, MainPID 0); SP6 ran it by hand. Deploy installs and enables it.
- `claude daemon --help` says the daemon "runs on demand and exits when the last client disconnects", and that service install is disabled in 2.1.289. Drill it: with no sessions running for 10 minutes, the unit is still active. If it exits, the unit needs `Restart=always`.
- For maintenance, `claude daemon stop --keep-workers` stops the supervisor and leaves detached sessions running; plain `stop` terminates them.
