# S-14.1 — Compose, systemd, tunnel

do:
1. `deploy/docker-compose.yml`:
   - hub on 127.0.0.1:7420;
   - `/data` volume;
   - runner socket mounted;
   - `restart: unless-stopped`.
2. systemd user units:
   - `marcel-runner.service`;
   - `marcel-redeploy.path` and `marcel-redeploy.service`;
   - `loginctl enable-linger`, so they run without a login.
3. Cloudflare: the `marcel-bot.com` ingress points to the hub, and only `/api/*` is exposed. That
   covers the app API (including `/api/health`, `/api/pair` and `/api/ws`) and the session
   endpoints `/api/session/adopt` and `/api/session/report`.
4. `make deploy`, `make logs`, `make health`.
5. `docs/operating.md`: install, pairing, upgrades, backups, triage.
done when:
- [ ] A reboot drill on the NUC brings the hub, runner and brain back with no manual steps (the log is in the PR).
- [ ] `curl https://marcel-bot.com/api/health` returns ok; without a token, `/api/tasks` returns 401;
  any path outside `/api/` is not reachable through the tunnel.

## From the spikes (2026-10-04)

- Install `/etc/claude-code/managed-settings.json` (root, once): `channelsEnabled: true`, `allowedChannelPlugins` = marcel@marcel-local plus telegram and imessage @claude-plugins-official (ADR-001).
- Register the `marcel-local` marketplace pointing at a deployed copy of `plugins/marcel/`, and install the plugin project-scoped in `~/marcel/brain` and in each worker workspace.
- Units: `marcel-claude-daemon.service` (`claude daemon run`, its own cgroup), `marcel-runner.service` (`Requires=` it; `RuntimeDirectory=marcel`, `RuntimeDirectoryPreserve=yes`, PATH with `~/.local/bin`), and `sudo loginctl enable-linger <user>`. Templates: `scratch/spikes/SP6-hub-runner-socket/`.
- Compose: the hub runs as `user: "${UID}:${GID}"`, mounts the runner directory (never the socket file) at `/run/marcel`, and mounts no `~/.claude`.
- After a Claude Code update, prefer `claude respawn --all` over restarting the supervisor unit, which stops every session.
- The hub image must contain `hub/migrations/`: `marcel_hub.db.MIGRATIONS_DIR` resolves it relative to the source tree (S-04.1).

## From the S-03.1 review

- The runner refuses to start while Claude's supervisor isn't up. `marcel-runner.service` comes up right after `marcel-claude-daemon.service`, so give it `Restart=on-failure` with `RestartSec=5` and a start limit that tolerates a slow supervisor start. Drill it: start both units cold, and the runner is healthy within 30 s.

## From the NUC, 2026-10-04

- `marcel-claude-daemon.service` is not installed or not active on the NUC today (`inactive`, MainPID 0); SP6 ran it by hand. Deploy installs and enables it.
- `claude daemon --help` says the daemon "runs on demand and exits when the last client disconnects", and that service install is disabled in 2.1.289. Drill it: with no sessions running for 10 minutes, the unit is still active. If it exits, the unit needs `Restart=always`.
- For maintenance, `claude daemon stop --keep-workers` stops the supervisor and leaves detached sessions running; plain `stop` terminates them.

  the hub at them by setting) and prove it with a container start in this story.
- ADR-002: the owner creates a fine-grained read-only GitHub token (Pull requests, Checks, Commit statuses: read) and puts it in `deploy/.env.local` as `MARCEL_GITHUB_TOKEN`.

## From reviews (2026-10-14)

- `/data` is a **host folder** bind-mounted into the hub (e.g. `~/marcel/data:/data`), not a Docker named volume: the
  brain's `MEMORY.md` and `memory/` are symlinks into the hub's memory folder on the host (S-06.1, `brain/README.md`).
- Render the brain workspace with `brain/render.py` (variables `AGENT_NAME`, `OWNER_NAME`, `MARKETPLACE_DIR`,
  `MEMORY_DIR`) into `~/marcel/brain`, then install the plugin there once.
- Set `MARCEL_TZ` (the hub's `tz` setting, default `Europe/Brussels`) in the hub's environment: the digests, schedules and usage-pause push use it, never the container's `TZ` (S-10.1, S-09.1, S-09.2).
- `MARCEL_GITHUB_TOKEN` in `deploy/.env.local`: a fine-grained, read-only token (ADR-002).
- APNs (S-08.2) in `deploy/.env.local`: `MARCEL_APNS_KEY` (the text of the `AuthKey_<id>.p8` file; on one line with
  `\n` for its line breaks, or only the lines between `BEGIN` and `END`), `MARCEL_APNS_KEY_ID`, `MARCEL_APNS_TEAM_ID`
  and `MARCEL_APNS_TOPIC` (the app's bundle id). All four or none; none means ntfy only. `MARCEL_APNS_SANDBOX=true`
  only for an app run from Xcode. Never put the `.p8` file in the image or the repo (`hub/README.md`).
- `MARCEL_BRAIN_CWD` on the hub: the brain workspace's path on the NUC (e.g. `/home/<you>/marcel/brain`). Unset, the
  hub starts no brain; set, it keeps one running and rolls it over at 04:00 in `TZ` (S-06.2, `hub/README.md`).
- First-run checks the reviews left for the NUC (board log `lead-nuc-checks`): transcript folder naming (S-03.4),
  the trust dialog and `~/.claude.json` keys on a real clone (S-03.5), one real cloud spawn and send (S-03.6),
  and `make -C plugins/marcel/tools test-live` recorded in `project/lessons/brain-skills-eval.md` (S-05.5).

## From S-11.1 (2026-10-15)

- **Protect `main` on GitHub** (branch protection on `shbunder/marcel`): only the owner may merge, no direct pushes,
  no force pushes. Without it a worker whose git login can merge could land unapproved code on `main`, and the next
  approved self-change would deploy it too (S-11.1 review; ADR-005).
- Mount the host's `~/marcel/state` into the hub at `/state` (`MARCEL_REDEPLOY_FLAG`, default `/state/redeploy.flag`).
  The hub writes the flag owner-only, so the hub container's `UID:GID` must be the user the redeploy units run as.
