# S-02.11 — Contract: workflow transcripts, the brain's animal, Claude update events

Lead only. Answers the contract requests `project/contract-requests/SP10-workflow-transcripts.md`,
`project/contract-requests/S-17.7.md` and `project/contract-requests/claude-auto-update.md`. runner-api 0.1.11 →
0.1.12, app-api 0.7.2 → 0.7.3. Everything is additive. What the hub does not read yet goes on its shrink-only pending
lists; the runner, hub and app work is in the follow-up stories below.

do:
1. **A workflow's agents (SP10).** The layout is `runner/tests/fake_claude/fixtures/transcripts/workflow-layout/`.
   - `transcript.schema.json`: four new types. `workflow_start` `{tool_use_id, run_id, name, task_id?, description?}`
     from the `Workflow` tool's launch result; `workflow_stop` `{tool_use_id, status, run_id?, summary?}` from its
     later `<task-notification>`; `workflow_agent_start` `{run_id, agent_id, label, phase?}` and `workflow_agent_stop`
     `{run_id, agent_id, summary?}` from the run's `journal.jsonl`. A new `TranscriptEvent.workflow_id` on every event
     of a workflow stream. Run id pattern `^wf_[A-Za-z0-9_-]{1,64}$` everywhere.
   - runner-api `GET /sessions/{id}/tail`: `workflow=<run id>` streams the journal; with `subagent=<hex>` it streams
     that agent's own file. One tail per file; the file must stay inside the session's folder, else 400.
   - app-api `TaskEventType` gains the four types, each `data` the transcript shape.
   - Simplest design: the hub only needs the journal stream to show a workflow's steps; the agent-file stream is in
     the contract so a later story can show an agent's own tool calls without another contract change.
2. **The brain's animal (S-17.7).** `PrepareBrain.persona.animal`, optional, the same values as app-api `LookAnimal`.
   Absent means the owner's default, a pink giraffe.
3. **Claude Code changed under Marcel (claude-auto-update).** Two `RunnerEvent` types: `runner.claude_changed` with
   `claude_change {from, to, expected}`, and `runner.supervisor_restarted` with `supervisor_restart {cause?,
   live_workers?, session_ids}`. Both carry `message`.
4. **Docs.** `contracts/README.md` and `avatar-sheet.schema.json` no longer name the retired
   `shared/avatar/pixel/build.py`; the bundled default sheet comes from the zoo (`make -C ios/AvatarKit sheet`).
5. **App decoder.** `make -C ios generate`; `QuestEntry` reads the four workflow types as helper lines until
   S-12.15 draws them as steps.

Deferred:
- **A usage bar per person on People** (`User.usage_share_week`): the hub's per-task usage (S-10.1) is a running total
  of five-hour-window points with no dates, so it cannot give a share of the last 7 days. The hub first has to keep
  dated attributions.
- S-05.4, S-07.2 `report_id` and S-11.1 items 2–3 stay deferred, as in S-02.10 (each needs hub work first).
