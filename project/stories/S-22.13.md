# S-22.13 — Buddies message each other

ADR-013 § One person, many buddies, with SP13's answers (`scratch/spikes/SP13-buddy-messages/RESULT.md`). Claude Code
carries the message (`SendMessage`, same machine); Marcel only shows it.

do:
1. **Who may send and receive.** The brain's `--settings` role file (`runner/src/marcel_runner/role_settings/`,
   like `worker.json`) carries `crossSessionInbound: accept` (was `refuse`, ADR-003). Not `brain/.claude/settings.json`:
   SP13 showed a project file may only make it stricter, so `accept` there is ignored. New `runner/src/marcel_runner/role_settings/side.json`, and the existing `worker.json`, get `crossSessionInbound: refuse`
   and `SendMessage`, `ListAgents` in `permissions.deny`, so side threads and quests can neither send nor receive.
   If SP13 found that a side thread's `--settings` cannot override the brain's project `accept`, follow its fallback.
2. **Addressing:** a buddy's brain is named by its slug (`--name`, already the case, S-17.7); the orchestrate skill says
   in two lines when to message another buddy ("ask Pip, she handles the family calendar") and that the reply comes
   back the same way.
3. **Showing it:** report from the RECEIVER (SP13: the sender's reply `to` is a socket path). S-02.16 chose the hook,
   not a runner transcript event: a plugin `UserPromptSubmit` hook on the receiver (`plugins/marcel/scripts/buddy_message.py`,
   5 s timeout, never blocks) reads the `<cross-session-message from-name=…>` prompt and posts
   `{from_name, text, msg_id}` to the hub's `POST /buddy-messages` (brain-api 0.2.0); the receiver is the caller's
   `X-Marcel-Session`. The prompt wrapper carries no `msg_id` (SP13 evidence): take it from the `origin.msg_id` of the
   newest `origin.kind: "peer"` line in the hook's `transcript_path`, and check on the NUC that the line is written
   before the hook runs. The hub dedupes on `msg_id` (201 first, 200 repeat) and stores a `buddy` message in both
   buddies' main conversations ("Marcel → Pip: …"); the app shows it from S-22.28. Remove the `PENDING_*` entries
   for the route, `MessageKind.buddy` and `Message.from_agent_id`/`to_agent_id` in `hub/tests/`.
done when:
- [ ] Tests: `runner/tests/test_role_settings.py` fails if the brain role file's value is not `accept`; `runner/tests/test_role_settings.py` fails if
      a worker or side settings file allows `SendMessage` or accepts inbound (both are controls: removing either
      fails a test).
- [ ] Hub tests: a buddy message lands in both conversations once; an unknown or archived `from_name` → 404
      `agent_not_found` and nothing stored; a repeated `msg_id` → 200 and nothing stored again.
- [ ] Live on the NUC: with two buddies, "ask Pip what's for dinner" in Marcel's chat → Pip's brain answers Marcel,
      and `GET /api/conversations/{id}/messages` for both buddies lists the exchange (pasted in the commit message).
