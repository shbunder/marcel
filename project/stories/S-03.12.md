# S-03.12 — Runner: say when Claude Code changes or its supervisor restarts

runner-api 0.1.12 `RunnerEvent` types `runner.claude_changed` and `runner.supervisor_restarted` (S-02.11, asked for by
`claude-auto-update`). Found live on the NUC: another `claude` updated the shared binary, the supervisor restarted onto
it (`cause=upgrade, live_workers=5` in `~/.claude/daemon.log`) and five sessions ended. See
`project/lessons/runner-built-ins.md`.

do:
1. On each watch poll, read the installed `claude --version` (the one `health.py` already reads; no extra process per
   poll if a cached value from the last minute exists). When it differs from the last one seen, send one
   `runner.claude_changed` with `claude_change {from, to, expected}` (`expected` = `runner/claude-version`) and a
   plain `message`, e.g. "Claude Code changed from 2.1.296 to 2.1.301; Marcel is tested with 2.1.296."
2. When the supervisor's pid differs between two polls, send one `runner.supervisor_restarted`: `session_ids` = the
   sessions live before and not listed after; `cause` and `live_workers` from the last
   `shutting down (cause=…, live_workers=…)` line of `~/.claude/daemon.log` when it can be read (left out when not).
   `message` in plain words, e.g. "Claude's supervisor restarted (upgrade); 2 running sessions ended."
3. Neither event replaces the `session.gone` of each ended session. The first poll after a runner start only records
   the version and pid; it sends nothing.
4. Docs: `docs/runner/watch.md` lists the two events.

The hub still guesses from `GET /health` (`hub/src/marcel_hub/claude_updates.py`); moving it onto these events is a
separate hub change, not this story.

done when:
- [ ] Test: a version change between two polls sends exactly one `runner.claude_changed` with the right `from`, `to`
  and `expected`; a third poll with the same version sends nothing.
- [ ] Test: a pid change sends one `runner.supervisor_restarted` naming the sessions that went away, with `cause` and
  `live_workers` read from a sample `daemon.log`, and without them when the log is missing.
- [ ] Every event the tests make validates against runner-api.yaml `RunnerEvent`.
- [ ] `make -C runner check` green.
