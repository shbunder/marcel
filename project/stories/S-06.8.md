# S-06.8 — Brain context by auto-compact

ADR-010: the brain keeps its context with Claude Code's built-in auto-compact instead of rolling itself over at 70 %
(S-06.7). After a compaction, a `SessionStart` hook with matcher `compact` puts back what the brain must not lose
(Claude Code docs, hooks-guide § "Re-inject context after compaction").

read first: project/decisions/ADR-010-claude-code-first.md, project/stories/S-06.7.md,
contracts/brain-api.yaml (auth: `X-Marcel-Secret`, `X-Marcel-Session`), project/contract-requests/S-06.8.md.

do:
1. **Auto-compact.** In `brain/.claude/settings.json` set `"autoCompactWindow": 200000`. The unit is tokens
   (100000 to 1000000, capped at the model's own window; Claude Code docs, env-vars § `CLAUDE_CODE_AUTO_COMPACT_WINDOW`).
   200k keeps the brain's turns small: it routes and summarises, the work happens in quests. Add `autoCompactWindow`
   to `ALLOWED_KEYS` in `brain/tests/test_settings.py`, and write the value and the reason in `brain/README.md`.
   `brain/CLAUDE.md` stays short (the persona test already caps it at 45 lines, well under 200).
2. **Hooks.** `plugins/marcel/hooks/hooks.json` runs `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/brain_context.py` (a
   `.py` file, so ruff, pyright and coverage in `make -C plugins/marcel/tools check` see it, like `adopt.py`) for
   two events. A command, not `type: http`: the hub secret is a file (`$CLAUDE_PLUGIN_DATA/hub-secret`) and an http
   hook can only put environment variables in headers.
   - `PreCompact`: write a short hand-over to `.marcel/handoff.md` in the session's folder: when and why (`manual`
     or `auto`), the open threads, and the last exchange (the last message to the session and its last words, read
     best-effort from the end of `transcript_path`). Print nothing.
   - `SessionStart`, matcher `startup|resume|compact`: print, in this order, the hand-over (after a compaction only,
     then remove it so an old one never comes back), `MEMORY.md` (first 8 KB), the open threads
     (`GET /brain/tasks?state=queued,starting,working,needs_you,silent`, one line each: `<id> <state> <title>`),
     and today's summary with the live sessions (`GET /brain/summary`, contract request S-06.8, landed by the
     lead's contract story S-02.9). This story does not wait for it: until that route exists, or when it answers
     404 or 503, one line says it is missing.
   A worker, adopted or not-yet-registered session gets 401/403 from the brain API: then print and write nothing,
   exit 0. If the hub cannot be reached, still give `MEMORY.md` and one line saying so, exit 0. A hook error must
   never block the session. `plugins/marcel/hooks/README.md` lists both hooks.
3. **Retire the context-size rollover.** In `hub/src/marcel_hub/brain.py`, the S-06.7 check on `turn_end` usage
   (`CONTEXT_FULL`, `turn_ended()`) runs only when a hub setting `brain_rollover_on_context` is true (default false).
   Declare it in `hub/src/marcel_hub/app.py` next to `brain_context_window`, hand it to the brain keeper the same
   way (with it off the hub does not read the brain's transcript at all), and list it in `hub/README.md`. Manual
   rollover, crash respawn and the rollover history stay as they are. Keep the nightly rollover as a safety net and
   say so in `brain/README.md`.
4. **Deploy note.** Add to `project/stories/S-14.1.md` a whole-path health check (hub → runner → the brain session
   answers a ping, not just "process up") and what the plugin's hooks need on the NUC.
done when:
- [ ] `brain/` tests: the rendered settings carry `autoCompactWindow`, and the settings JSON validates.
- [ ] Tests in `plugins/marcel/tools/tests/test_brain_context_script.py` against the hub in-process: start, resume
  and compact give notes + open threads + summary; summary route missing → the "missing" line; 401/403 → no output
  and no hand-over; hub down → `MEMORY.md` + the "unreachable" line; the hand-over is written before a compaction,
  given once after it and never on a plain start; the last exchange of a recorded transcript; exit 0 in every case.
- [ ] Hub tests: with the setting off, a turn past 70 % does not roll over; with it on, it rolls over once (the
  S-06.7 test, now under the setting).
