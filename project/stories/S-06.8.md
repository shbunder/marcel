# S-06.8 — Brain context by auto-compact

ADR-010: the brain keeps its context with Claude Code's built-in auto-compact instead of rolling itself over at 70 %
(S-06.7). After a compaction, a `SessionStart` hook with matcher `compact` puts back what the brain must not lose
(Claude Code docs, hooks-guide § "Re-inject context after compaction").

read first: project/decisions/ADR-010-claude-code-first.md, project/stories/S-06.7.md,
contracts/brain-api.yaml (auth: `X-Marcel-Secret`, `X-Marcel-Session`), project/contract-requests/S-06.8.md.

do:
1. **Auto-compact.** In `brain/.claude/settings.json` set `"autoCompactWindow": 200000`. The unit is tokens
   (100000 to 1000000, capped at the model's own window; Claude Code docs, env-vars § `CLAUDE_CODE_AUTO_COMPACT_WINDOW`).
   200k keeps the brain's turns small: it routes and summarises, the work happens in quests. Add `autoCompactWindow`
   to `ALLOWED_KEYS` in `brain/tests/test_settings.py`, and write the value and the reason in `brain/README.md`.
2. **Re-inject after compaction.** A plugin hook in `plugins/marcel/hooks/hooks.json`: `SessionStart`, matcher
   `compact`, `type: command`, running `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/after_compact.py` (a `.py` file, so
   ruff, pyright and coverage in `make -C plugins/marcel/tools check` see it, like `adopt.py`). A command, not `type: http`: the hub
   secret is a file (`$CLAUDE_PLUGIN_DATA/hub-secret`) and an http hook can only put environment variables in
   headers. The script reads `session_id` from the hook's stdin JSON and prints, in this order:
   - `MEMORY.md` from the session's working folder;
   - the open tasks: `GET /brain/tasks?state=queued,starting,working,needs_you,silent`, one line each
     (`<id> <state> <title>`);
   - today's summary from the hub (contract request S-06.8, landed by the lead's contract story S-02.9). This story
     does not wait for it: until that route exists, or when it answers 404 or
     503, skip this part with one line saying it is missing.
   A worker or adopted session gets 403 `not_brain` from the brain API: then print nothing and exit 0. If the hub
   cannot be reached, print `MEMORY.md` and one line saying the hub is unreachable, and still exit 0. A hook error
   must never block the session.
3. **Retire the context-size rollover.** In `hub/src/marcel_hub/brain.py`, the S-06.7 check on `turn_end` usage
   (`CONTEXT_FULL`, `turn_ended()`) runs only when a hub setting `brain_rollover_on_context` is true (default false).
   Declare it in `hub/src/marcel_hub/app.py` next to `brain_context_window`, hand it to the brain keeper the same
   way, and list it in `hub/README.md`. Manual rollover, crash respawn
   and the rollover history stay as they are. Keep the nightly rollover as a safety net and say so in
   `brain/README.md`.
done when:
- [ ] `brain/` tests: the rendered settings carry `autoCompactWindow`, and the settings JSON validates.
- [ ] Tests in `plugins/marcel/tools/tests/test_after_compact_script.py` against a fake hub: brain session → `MEMORY.md` + open tasks + summary; summary
  route missing → the "missing" line; 403 → no output; hub down → `MEMORY.md` + the "unreachable" line; exit 0 in
  every case.
- [ ] Hub tests: with the setting off, a turn past 70 % does not roll over; with it on, it rolls over once (the
  S-06.7 test, now under the setting).
- [ ] `brain/README.md` says how the brain keeps its context now, and why the old rollover is off.
