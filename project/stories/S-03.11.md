# S-03.11 — Runner: tail a workflow's journal and agents

runner-api 0.1.12 `GET /sessions/{id}/tail` and transcript.schema.json's `WorkflowStart`, `WorkflowStop`,
`WorkflowAgentStart`, `WorkflowAgentStop` and `workflow_id` (S-02.11). The recording is
`runner/tests/fake_claude/fixtures/transcripts/workflow-layout/` (its README has the layout).

do:
1. **Main transcript.** A `tool_result` whose line's `toolUseResult` has `status: async_launched` and
   `taskType: local_workflow` gives a `workflow_start` after the `tool_result`: `run_id` = `runId`, `task_id` =
   `taskId`, `name` = `workflowName` (else `workflow`), `description` = `summary`. A user line whose text is a
   `<task-notification>` with a `<tool-use-id>` the runner saw launch a workflow gives `workflow_stop`: `status` from
   `<status>` (`completed`, `failed`, `stopped`; `killed` → `stopped`; anything else `unknown`), `summary` from
   `<summary>` cut to 2 KB, `run_id` when known. That line no longer becomes a plain `text` event.
2. **The journal.** `tail?workflow=<run id>` reads `<session-id>/subagents/workflows/<run id>/journal.jsonl`.
   `started` → `workflow_agent_start` (`label` else `agent`, `phase` when set); `result` → `workflow_agent_stop`
   (`summary` = the `result` as text, or compact JSON when it is not a string, cut to 2 KB). `launched` gives nothing.
   Every event carries `workflow_id`.
3. **An agent's file.** `tail?workflow=<run id>&subagent=<hex>` reads `agent-<hex>.jsonl` in that folder with the
   normal normaliser; events carry `workflow_id` and `subagent_id`.
4. **Safety.** Check both params against their patterns, resolve the path and refuse (400 `bad_request`) anything that
   is not inside the session's own folder, symlinks included. One tail per file (session, workflow, subagent); the
   newest wins, as today. A file that does not exist yet is waited for.
5. Docs: `docs/runner/transcript.md` gets the workflow mapping.
