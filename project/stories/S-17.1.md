# S-17.1 — Users and the owner

do:
1. At hub start-up (and in `marcel-hub setup`), make sure the owner row exists: id `usr_owner`, role `owner`, name
   from `MARCEL_OWNER_NAME`. Existing phones keep working.
2. `marcel-hub setup` (run once on the NUC, safe to repeat): the owner, the owner's agent "Marcel" (giraffe, rose,
   professional, slug `marcel`) with its main conversation and Inbox if missing, and a QR for the owner's first phone.
   `marcel-hub pair` keeps working for the owner. The owner is the person whose Claude login the NUC uses (B-38).
3. `require_owner`, applied to every operation marked `x-owner-only` in the contract: list, add and remove people,
   pairing codes for anyone. Adding a person stores the user; their agent is S-17.4/S-17.7. Removing a person
   revokes their phones, stops their quests and sets `agent.archived_at` (S-17.7 makes the brain keeper, schedules and
   digests skip archived agents). The owner cannot remove themselves (409).
4. Pairing codes already carry `user_id` (`auth/tokens.py:76-119`); `POST /users/{id}/pairing-codes` makes one for
   that person.
done when:
- [ ] A member gets 403 on every `x-owner-only` operation; the test reads the list from the contract, so a new
      owner route without `require_owner` fails it.
- [ ] A phone paired with a member's code belongs to that member.
- [ ] `setup` twice leaves one owner and one agent; removing a person → their tokens get 401 at once; removing the
      owner → 409.
