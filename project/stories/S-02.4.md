# S-02.4 — Mock hub for the app

do:
1. A new lane `mock-hub/` (uv project `marcel_mock_hub`, Python 3.12, same gate as `hub/`: ruff, pyright,
   pytest, coverage ≥ 90 %), added to the root `make check`. It lives outside `contracts/`, which only the
   lead edits; it **reads** `contracts/app-api.yaml` and `contracts/events.schema.json`.
2. A small FastAPI app that serves every operation in `contracts/app-api.yaml` under `/api`, answering with
   the contract's examples (any device token works; `POST /api/pair` accepts any code), plus `GET /api/ws`
   speaking `events.schema.json` (`hello`, then scenario events, replay with `?since=`).
3. A scripted scenario player, triggered by `POST /api/conversations/{id}/messages`: the user message →
   a "started" milestone → task events (text, tool_call, diff) → an approval card + `needs_you` →
   (after `POST /api/approvals/{id}`) `working` → done milestone + PR artifact. Agent state follows
   (`thinking`, `working(1)`, `needs_you`, `done`, `idle`) so the avatar can be driven too.
4. `make mock-hub` runs it on `127.0.0.1:7499`; `mock-hub/scripts/walk.sh` is a curl + websocat (or Python)
   script that walks the whole scenario.
done when:
- [ ] Every response and every WebSocket frame the mock emits validates against the contract (a test
  validates them with the same registry the contract tests use).
- [ ] A test drives the full scenario over HTTP + WS and asserts the event order.
- [ ] `walk.sh` runs end to end against `make mock-hub`, and its output is pasted in the PR.
not in scope: persistence, auth, realistic data beyond the contract's examples.
