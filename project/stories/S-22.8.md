# S-22.8 — A public address with Tailscale Funnel

ADR-013 question 1. Read first: `scratch/spikes/SP12-funnel/RESULT.md` (the exact commands and what the first
`funnel` asks for), `deploy/Makefile` `tunnel` and `tunnel-rules` (today's named tunnel and its path checks).

do:
1. `marcel connect` (Tailscale, the default): download `tailscale` and `tailscaled` for this system into
   `~/.marcel/tailscale/` (release checksum checked); add the `tunnel` service (S-22.4 table) running `tailscaled` in
   user-space mode with its state and socket under `~/.marcel/tailscale/`; run `tailscale up` and show its sign-in link
   in plain words ("Open this link to connect Marcel to your free Tailscale account"); then publish **only** `/api` to
   `http://127.0.0.1:7420/api` with Funnel, showing the policy link if Tailscale asks for it.
2. **Check before saying done:** through the public address, `/api/health` is ok; `/api/tasks` without a token is
   401; `/channel` and `/api/../channel` (`curl --path-as-is`) do not reach the hub. Any failure: say which, change
   nothing else.
3. Write `public_url` (`marcel.toml`, S-22.2) and `~/.marcel/hub-url`; then print the pairing QR (`marcel pair`, which
   wraps `marcel-hub pair`).
4. **Advanced:** `marcel connect cloudflare <hostname>` keeps today's named tunnel (`deploy/cloudflared/marcel.yml`),
   run as the user's `tunnel` service instead of the system unit (no sudo), with the same three checks. The NUC uses
   this.
5. `marcel disconnect` removes the Funnel config, logs the node out and stops the `tunnel` service.
6. `docs/operating.md` § Connect: both ways, and what the person sees on the phone if the address changes (pair again).
7. **Funnel watchdog** (SP12: after sleep and a network change the user-space `tailscaled` kept saying "Funnel on"
   while the address stayed dead for 15 minutes; restarting it brought the same address back in 72 s). The `tunnel`
   service checks its own public address (`GET <public_url>/health`) after a wake, after a network change, and every
   5 minutes. If it does not answer for 2 minutes, it restarts `tailscaled` (only Marcel's), and logs in plain words
   ("Marcel's public address stopped answering after the Mac woke; restarted the connection"). After 3 restarts in an
   hour that did not help, it stops trying and sends one notice ("Marcel can't be reached from outside. Open
   `marcel status` on the Mac."). It tells the hub, which says so through the push relay (S-22.17).
done when:
- [ ] On the Mac (non-admin user): `marcel connect` ends with the QR; the phone on mobile data pairs and the chat works.
- [ ] After closing the lid 10 minutes and switching Wi-Fi, the app reconnects with no command typed (time recorded;
      the watchdog may restart `tailscaled` on the way, and the log says so).
- [ ] Unit tests for the watchdog with a fake clock and a fake address: a dead address restarts `tailscaled` after
      2 minutes and not before; a live one never does; after 3 failed restarts in an hour it stops and sends the notice
      once. A test goes red when the restart is removed.
- [ ] Unit tests: each failed check stops `connect` with its sentence and writes no `public_url`.
