# SP11 — Marcel's sessions on a Mac laptop, without Docker

For F22 (ADR-013, `plan/05-install-anywhere.md`). Everything Marcel's background sessions rely on was proven on the
Linux NUC only. Run this on a Mac with a **fresh macOS user account** that is not an admin, logged in to Claude Code.

**Questions and steps:**
1. **Channel allowlist as a drop-in.** Write `/Library/Application Support/ClaudeCode/managed-settings.d/50-marcel.json`
   (admin password once) with `channelsEnabled` and `allowedChannelPlugins` (marcel@marcel-local, plus telegram,
   imessage and discord from `claude-plugins-official`). Install the plugin from a `marcel-local` directory marketplace
   into a scratch folder. Does `claude --bg --channels plugin:marcel@marcel-local` register the channel
   (`Channel notifications registered` in its debug log)? Does `/status` list "(drop-ins)"? Note what happens when a
   `managed-settings.json` with another `allowedChannelPlugins` also exists (which list wins).
2. **The supervisor under launchd.** A LaunchAgent in `~/Library/LaunchAgents` runs `claude daemon run` with
   `KeepAlive`. Start a background session; `claude agents --json` sees it; `launchctl kickstart -k` of a *second* job
   (the runner stand-in) does not end it. Which pid or label tells a runner that the supervisor is its own job (the
   Linux runner reads `/proc/<pid>/cgroup`, `runner/src/marcel_runner/health.py`)?
3. **The login from a LaunchAgent.** With the login in the Keychain, does `claude -p "/usage"` run from the
   LaunchAgent? After a reboot and automatic login? Before anyone logs in (expected: nothing runs)?
4. **A private copy of the pinned binary.** Copy the pinned version's binary from `~/.local/share/claude/versions/`
   to `~/marcel/claude/<version>/claude`. Do `--bg`, `claude agents --json`, `respawn` and channels work from the copy
   while the user's own `~/.local/bin/claude` is a newer version? What does the supervisor do when two versions talk
   to it?
5. **Sleep and wake.** With a background session mid-task: close the lid for 10 minutes, open it, switch Wi-Fi. Does
   the session carry on, does the supervisor survive, how long until the channel reconnects to a hub on 127.0.0.1?
   Does `caffeinate -i -w <pid>` (no admin) keep the Mac awake with the lid open on battery? With the lid closed?
6. **Trust.** Does writing `projects["<path>"].hasTrustDialogAccepted: true` in `~/.claude.json` (what the runner
   does today) let `claude --bg` start in that folder on macOS?

**Pass:** steps 1–4 work → F22 goes ahead as ADR-013 says. **Fallback** for step 1: the brain runs in a terminal
session under `script`/tmux with the development-channels flag (ADR-001 option B), noted in ADR-013. For step 4: point
Marcel at Claude's own versions folder and re-pin after each user update.
