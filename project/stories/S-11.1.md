# S-11.1 — Self-change tasks and approval

do:
1. A self-change is an ordinary task against `shbunder/marcel` that must end with a PR artifact flagged
   `self_change=true`. The hub sets the flag from the PR address; a worker cannot set or avoid it.
2. The hub posts an approval card ("Marcel wants to change itself: <PR title>") with the diff stats, read with
   the read-only GitHub token.
3. Approve → the hub records it and tells the owner to merge the PR on GitHub; it never merges (ADR-005). When the
   PR refresh sees it merged **and** approved in the app → `request_redeploy(sha)`, with the SHA from GitHub's
   merged-PR answer only. Merged without that approval → no redeploy, one plain alert.
4. Deny → close the card, tell the owner they may close the PR on GitHub, and ask the worker that made it to
   close it with its own git credentials (the hub's token is read-only).
5. The `self-improve` skill tells the brain and the worker how to make a self-change: branch, tests, PR, never
   merge, never restart.
done when:
- [ ] Test: no redeploy without an approval in the app, and removing the check makes this test fail.
- [ ] Test: deny closes the card and asks the worker to close the PR; a denied PR merged anyway is not redeployed.
