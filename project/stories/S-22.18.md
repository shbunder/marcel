# S-22.18 — Keep the Mac awake while a quest runs (optional)

(`S-22.21` is in `depends:` only so that `deploy/cli/` is not changed by two stories at once.)

An option, never a requirement (ADR-013 question 4). Off by default. Read first: SP11 step 5: `caffeinate -i -w <pid>`
holds "prevent idle sleep" without admin and lets go when that process ends (measured with the lid open, on power);
a closed lid sleeps regardless (Apple), and SP11 still owes the lid, battery and Wi-Fi measurements.

do:
1. `runner/src/marcel_runner/awake.py`: while the setting is on and at least one worker session is live, the runner
   holds one `caffeinate -i -w <runner pid>` child (no admin, and it cannot outlive the runner); it ends it when the
   last worker ends or the runner stops. Linux:
   `systemd-inhibit --what=idle` when present, else nothing and one log line.
2. Setting: `MARCEL_KEEP_AWAKE=while_working` in the runner's service environment, set by
   `marcel config keep-awake on|off` (restarts only the runner, through `marcel`, as a person's command).
3. `docs/runner.md`: what it does and what it cannot do (a closed lid on battery still sleeps).
done when:
- [ ] Tests with a fake `caffeinate`: started once for two live workers, stopped when both end, never started with
      the setting off.
- [ ] Test with a fake `systemd-inhibit` (Linux): started once while workers run, stopped after; absent → one log
      line, nothing started.
- [ ] On the Mac: `pmset -g assertions` shows a "caffeinate command-line tool" assertion on behalf of the runner's
      pid only while a quest runs.
