# S-04.11 — Living artifacts and project boards

do:
1. `artifact_version`. `report(artifact)` and `artifacts_publish` without an id create an artifact (v1); with
   an id they add a version. `GET /artifacts/{id}/versions`; content by version. WS `artifact.created` (v1)
   and `artifact.updated` (v2+).
2. The first version of an artifact produced by a task adds an `artifact` message to the main chat (the
   item-get milestone); later versions do not.
3. **Boards:** every project has a `board` artifact (dashboard JSON). The hub rebuilds it, debounced to once per
   10 s per project, on any task, approval or artifact change in that project: *waiting on you*, *in flight*
   (with step progress), *recent results* (with their items), *upcoming schedules*, and Marcel's notes added
   through `board_note`. A rebuild is a new version only when the content changed. No brain turn.
4. The morning digest (S-09.2) is published as the agent's board artifact, not a long message.
done when:
- [ ] A version bump does not post a second item-get message; an unchanged rebuild does not create a version.
- [ ] Board test: an open approval appears under "waiting on you" and disappears when answered.
