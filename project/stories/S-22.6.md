# S-22.6 — Marcel follows the user's Claude Code on a Mac, and the one password prompt

ADR-013 question 5, as amended after SP11 (`scratch/spikes/SP11-mac-services/RESULT.md` step 4): a Mac login has one
Claude supervisor, every background session runs on its version, and the user's own newer `claude` (or their
automatic update) takes it over and moves Marcel's sessions onto its version. A private pinned copy cannot hold, so
on a Mac Marcel **does not pin**: it runs the user's own `claude` and says when the version changes. The NUC keeps its
pin and its system-wide managed settings unchanged (Docker mode, and after S-22.24 a native install that keeps
`runner/claude-version` enforced).

This story also owns turning S-03.10's version refusal into a warning on Mac installs: today the runner answers 422
`claude_version` on every start when `claude --version` is not `runner/claude-version`, which on a Mac would stop
Marcel after every update of the user's Claude Code.

Read first: SP11 RESULT.md steps 1 and 4, `runner/src/marcel_runner/health.py` and `server.py` (the pin check,
S-03.10), `watch.py` (`runner.claude_changed`, S-03.12), `hub/src/marcel_hub/claude_updates.py` (S-04.17),
contracts/runner-api.yaml after S-02.13 item 11 (`claude_change.expected` optional).

do:
1. **No pin on a Mac.** The runner reads `MARCEL_CLAUDE_PIN` (`enforce` | `off`; default `enforce`, so the NUC and
   every existing test are unchanged). `marcel install` sets `off` in the runner's service environment on **every
   native install except the owner's NUC** (a Linux desktop or a joined computer, S-22.21, shares one supervisor with
   its user the same way); the NUC stays `enforce` (Docker mode now, and `marcel migrate` writes `enforce`, S-22.24).
   It points `MARCEL_CLAUDE` at the user's own `~/.local/bin/claude`; it sets no `DISABLE_AUTOUPDATER` (the user's
   Claude Code updates as it always did). It checks `claude --version` runs and the login works, and stops with one
   plain sentence when either fails.
2. **Warn, don't refuse.** With `off`: `Health.claude_version_expected` is left out, a version mismatch never makes
   `ok` false, and no start answers 422 `claude_version`. `claude --version` is still read on every poll; a change
   still sends `runner.claude_changed`, without `expected`. With `enforce`, everything stays as S-03.10 and S-03.12
   built it.
3. **The hub's words.** `claude_updates.py`: a `runner.claude_changed` without `expected` gives one note in the main
   conversation, not urgent, once per version: "Claude Code on your Mac updated to 2.1.300. Marcel carries on with it."
   - `on_runner_event` reads `expected` with `.get` (today `change['expected']` would raise `KeyError`).
   - `check()` at start-up passes `Health.claude_version_expected` to `_saw`, which today returns early when it is
     empty. With no `expected`, `_saw` compares the version with `state['seen']`, tells once per new version, and sets
     no `change` and no urgent push, so a version changed while the hub was down is told once.
   - A `runner.supervisor_restarted` with an empty `session_ids` says nothing, whatever its `cause` (SP11: a takeover
     by a newer `claude` logs `cause=signal`, an update `cause=upgrade`; the new supervisor adopts the sessions and
     resumes them on its version; none ended). Today's code already says nothing then: keep it, with a test.
4. **The channel allowlist as a drop-in.** Do not start this item before SP11 step 1 is recorded (the macOS drop-in is
   unproven). `deploy/managed-settings.json` keeps only `channelsEnabled` and `allowedChannelPlugins` (no `env`). A
   new `deploy/managed-settings.nuc.json` keeps today's full content, `env.DISABLE_AUTOUPDATER` included, for the
   pinned NUC (`docs/operating.md` points the NUC at it; S-22.24 installs it). The install explains in one sentence why it needs the password ("Claude Code
   only lets an administrator allow Marcel's chat channel"), then writes it to
   `/Library/Application Support/ClaudeCode/managed-settings.d/50-marcel.json` (macOS, through `sudo` in the terminal)
   or `/etc/claude-code/managed-settings.d/50-marcel.json` (Linux). Skipped when the same content is already there.
   An existing `managed-settings.json` with its own `allowedChannelPlugins`: the install stops and says which list to
   merge by hand (SP11 step 1 says which wins; until it has run, the install stops whenever both exist). A user who is
   not an administrator, or who declines the password: one sentence ("Marcel's chat channel needs an administrator
   once; ask one to run `marcel install` again"), a non-zero exit, and nothing half-written.
5. **The NUC is untouched.** Docker mode (S-22.4): no drop-in, no change to `/etc/claude-code/managed-settings.json`,
   `MARCEL_CLAUDE_PIN` stays `enforce`, so an unattended NUC redeploy never stops or asks for a password.
6. The drop-in path goes in the install manifest; uninstall removes it (with the password again).
7. `docs/operating.md`, `docs/runner.md` and `docs/runner/built-ins.md` (its line on the unconditional pin and
   `DISABLE_AUTOUPDATER`): a Mac follows the user's Claude Code (why: SP11), what the owner is told when it changes,
   the drop-in, and that the NUC keeps its pin with `managed-settings.nuc.json`.

done when:
- [ ] Runner unit tests: with `MARCEL_CLAUDE_PIN=off` and the fake claude reporting another version, spawn, resume,
      fork and cloud start succeed, `/health` has no `claude_version_expected` and `ok` stays true, and a change sends
      `runner.claude_changed` without `expected`; with `enforce` (and with the variable unset) the existing 422
      `claude_version` tests still pass and still fail when the check is removed (inert-controls rule).
- [ ] Hub unit tests: a change without `expected` gives exactly one not-urgent note per version; a version changed
      while the hub was down (start-up `check()` with no `claude_version_expected`) is told once, and a second hub
      restart tells nothing; a supervisor restart with `cause: signal` or `upgrade` and no ended sessions gives none.
- [ ] Install unit tests: the drop-in is written once; an existing different allowlist stops the install with its
      sentence; a declined password exits non-zero with its sentence and writes nothing; in Docker mode neither the
      drop-in nor `MARCEL_CLAUDE_PIN` is touched; a native non-NUC install gets `off`.
- [ ] On the Mac: after `marcel install`, a brain session registers its channel; then the user's own newer `claude`
      starts a session (or `claude update` runs): Marcel's sessions carry on on the new version, the owner gets the
      one note, and `deploy/health.sh` exits 0.
