# S-22.6 — Marcel's own Claude Code version, and the one password prompt

Today the pin shares `~/.local/bin/claude` with the user's own sessions, and the system-wide managed-settings file also
turns updates off for them (`docs/operating.md` § Upgrading Claude Code). ADR-013 question 5. Read first:
`scratch/spikes/SP11-mac-services/RESULT.md` steps 1 and 4.

do:
1. **A private copy.** `marcel install` installs the pinned version (`runner/claude-version`) with Claude's own
   installer when it is not on disk, then copies its binary from `~/.local/share/claude/versions/<v>` to
   `~/marcel/claude/<v>/claude` (checking `--version`). Every Marcel service runs that path (`MARCEL_CLAUDE`, and
   `PATH` with `~/marcel/claude/<v>` first) with `DISABLE_AUTOUPDATER=1`. If SP11 step 4 failed, follow its fallback
   instead and say so in `docs/operating.md`.
2. **The channel allowlist as a drop-in.** `deploy/managed-settings.json` keeps only `channelsEnabled` and
   `allowedChannelPlugins` (no `env`). The install explains in one sentence why it needs the password ("Claude Code
   only lets an administrator allow Marcel's chat channel"), then writes it to
   `/Library/Application Support/ClaudeCode/managed-settings.d/50-marcel.json` (macOS, through `sudo` in the terminal)
   or `/etc/claude-code/managed-settings.d/50-marcel.json` (Linux). Skipped when the same content is already there.
   An existing `managed-settings.json` with its own `allowedChannelPlugins`: the install stops and says which list
   to merge by hand (SP11 step 1 says which wins).
3. **Docker mode** (S-22.4, the NUC until S-22.24): skip the private copy and the drop-in and leave the existing
   `/etc/claude-code/managed-settings.json` alone, so an unattended NUC redeploy never stops or asks for a password.
4. The path goes in the install manifest; uninstall removes it (with the password again).
5. `docs/operating.md`: the pin, the copy, the drop-in, and that the user's own `claude` now updates freely.
done when:
- [ ] On the Mac: after `marcel install`, `~/marcel/claude/<v>/claude --version` is the pinned version; a brain
      session registers its channel; then `claude update` for the user's own install leaves Marcel's sessions and
      `deploy/health.sh` (exit 0) unchanged.
- [ ] Unit tests: the drop-in is written once; an existing different allowlist stops the install with its sentence;
      in Docker mode neither the copy nor the drop-in is touched.
