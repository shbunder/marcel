# S-11.2 — Redeploy and rollback

do:
1. `request_redeploy` writes the `~/marcel/state/redeploy.flag` file (sha). A `marcel-redeploy.path` unit runs
   `redeploy.sh`:
   - pull;
   - rebuild the hub image;
   - restart the runner if `runner/` changed;
   - sync the brain template.
2. A health watchdog polls `/api/health` for 120 s. On failure it runs `git revert` on the merge, redeploys, and notifies.
done when:
- [ ] A live drill on the NUC: a deliberately broken commit is rolled back automatically, with a notification received.

## From S-11.1 (2026-10-15)

- The hub writes the flag (40-hex SHA + newline) owner-only via a temp file and rename, from `MARCEL_REDEPLOY_FLAG`
  (`/state/redeploy.flag` in the container). `redeploy.sh` must run as the same user, read only a 40-hex SHA from it,
  check that SHA is on `origin/main`, and never treat the content as anything else (`.claude/rules/self-modification.md`).
- ADR-005: the owner merges self-changes on GitHub; the hub writes the flag only for a merge the owner approved in the
  app at that exact commit, into `main`.

## From the S-03.10 review (2026-10-14)

- The watchdog must not roll back on a Claude Code version drift. `deploy/health.sh` exits **2** when the only
  problem is that the installed `claude` differs from the pin (`runner/claude-version`): everything runs, the runner
  only refuses new sessions until `deploy/install-claude.sh` runs. A merge did not cause that, so reverting it would
  undo an unrelated change. Treat 0 as healthy, 1 as broken (roll back), 2 as "not this merge" (no rollback;
  notify the owner to run `deploy/install-claude.sh`). `GET /internal/health` shows it as `runner.state:
  version_drift` with `claude_version` and `claude_version_expected` (docs/operating.md, exit codes).
