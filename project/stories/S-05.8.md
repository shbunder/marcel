# S-05.8 — Session-end hooks

ADR-010: the hub hears from Claude Code itself when a session ends, instead of relying on a worker remembering to
call `report()`. Today the runner's 2-second poll sees the process end, but not why, and not whether the worker
reported first.

read first: project/decisions/ADR-010-claude-code-first.md, contracts/channel-protocol.md (identity and secret),
contracts/task-states.md, contracts/session-api.yaml `/channel/session-end` and channel-protocol.md § Session-end hooks (added by S-02.9;
this story waits for it).

do:
1. **Hooks.** Add two `type: command` hooks to the existing `plugins/marcel/hooks/hooks.json` (S-06.8 creates it),
   both running `python3 ${CLAUDE_PLUGIN_ROOT}/scripts/session_end.py` (a `.py` file, tested like `adopt.py`; a command, not `type: http`: the hub secret is the file
   `$CLAUDE_PLUGIN_DATA/hub-secret`, and an http hook can only put environment variables in headers):
   - `SessionEnd` (`timeout` 5 s): POST the hook's `session_id` and `reason` to the hub's session-end route
     (session-api.yaml `sessionEnded`). Exit 0 whatever happens.
   - `Stop`: ask the same route whether this session owes a report. If the hub says yes and the hook input's
     `stop_hook_active` is false, print `{"decision": "block", "reason": "Call report(done) or report(failed)
     before you finish."}`. Otherwise allow. So a worker is reminded once, never looped.
   Auth is the channel's: `X-Marcel-Secret` from the file, the session known because the runner reported its id.
2. **Hub.** A new `hub/src/marcel_hub/channel/session_end.py` with the route from the contract request, registered
   from `channel/__init__.py`; take it off `PENDING_SESSION_OPERATIONS` in `hub/tests/test_contract_routes.py`. Reuse `tasks/states.py` and the `TaskState.failed` path in `channel/gateway.py`
   without editing either (four other wave-4 stories edit `gateway.py`). If the runner's poll already moved the
   task to `done` or `failed`, only record the end reason. Otherwise:
   - a brain or side-thread session: record the end and answer "no report owed" (the brain keeper's crash respawn
     already handles a brain that ends);
   - a worker that already reported `done` or `failed`: record the end reason in the task's events, nothing else;
   - a worker that ended without a report: the task goes to `failed` with reason `ended_without_report`
     (`state` event), and the brain gets a system event saying which task ended and the end reason;
   - an unknown session: 401, exactly like the channel.
