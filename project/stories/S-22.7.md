# S-22.7 — Redeploy and rollback without Docker, on both systems

The only legal restart path (`.claude/rules/self-modification.md`, ADR-005) must keep working after Docker is gone and
on macOS. `deploy/redeploy.sh` uses `flock`, `stat -c`, `/usr/bin/python3` and `make -C deploy install` (Docker
rebuild). Opens a PR for the owner (ADR-012: it touches the self-change path).

do:
1. **Portable:** the lock through `marcel lock` (Python `fcntl`) or a `mkdir` lock; file size through Python;
   `python3` from `uv run`. Runs under bash 3.2 (macOS) and bash 5.
2. **Deploy** = `marcel install --yes` with `MARCEL_SKIP_HEALTH=1`, which runs `uv sync` and restarts the hub and the
   runner through the service table (never the supervisor, as today). Health: the pre-change `health.sh` copy, as
   today.
3. **Rollback where nobody can push.** When `git push --dry-run origin` fails at the start (a colleague's install
   cloned over https), the rollback checks out the previous commit locally (`git reset --hard <previous>` on the
   deployed copy only), deploys it, checks health, and writes `rolled_back` with "reverted on this computer only".
   The owner's install (pushable) behaves exactly as today.
4. `deploy/tests/test_redeploy.sh` is portable (it is run on the Mac in S-22.10) and gains: the local-only rollback; a test that **deletes the rollback** and expects a red run (inert-controls rule).
5. `docs/operating.md` § Self-changes: the macOS trigger (`WatchPaths`), the local rollback.
done when:
- [ ] `bash deploy/tests/test_redeploy.sh` passes on the NUC; with the rollback commented out it fails naming the
      rollback.
- [ ] A drill on the NUC (still on Docker: the deploy step rebuilds the container, S-22.5 step 6) with `MARCEL_REDEPLOY_BRANCH` (docs/operating.md, "Self-changes"): a broken commit is rolled
      back and the hub tells the owner; the log is in the PR.
