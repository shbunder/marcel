# S-20.1 — Coding projects start well

do:
1. A `project-kickoff` skill. When a project with a repo is created, or the first coding quest runs in a repo without
   these, Marcel starts one "Kickoff" quest that adds, in one PR, what is missing:
   - a `CLAUDE.md` that names the one check command;
   - that check command (`make check`, `npm test`, …);
   - a CI workflow that runs it;
   - a pull-request template.
   It never overwrites an existing file, and it writes the check command into the project notes.
2. The "what is missing" check is a small script, `project-kickoff/scripts/missing.py`, that the skill runs.
3. One line in `orchestrate` that triggers it; the skill is listed in `skills/README.md`.
4. **The project brief (ADR-011).** The hub already writes a project's notes file when the project is made
   (`hub/src/marcel_hub/projects/store.py`, `_first_notes`). Make it start with these headings, in order:
   **What it is for** (the project's `goal`, or "(not known yet)"), **Where the work happens** (the repo, if any),
   **How to check the work** (the kickoff quest fills in the check command here), **What needs a go-ahead first**
   ("(not known yet)"), **Notes** (where `report(note)` appends, as today). Existing notes files are not rewritten.
   `worker-protocol` gets one line: read "How to check the work" and "What needs a go-ahead first" before starting.
done when:
- [ ] `missing.py` unit tests: a bare repo → all four; a complete repo → none (so no PR).
- [ ] Hub test in `hub/tests/test_projects*`: a new project's notes file has the five headings in order, with the goal
  and repo filled in; an existing notes file is left as it is. `make -C hub check` green.
- [ ] `make -C plugins/marcel/tools check` passes; the scripted brain replay starts a kickoff quest for a new project with a repo.
