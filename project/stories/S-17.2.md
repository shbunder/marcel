# S-17.2 — Every request is checked against its person

Today several routes assume one person. This story closes them. (Code read on 2026-10-13: not scoped
`tasks/routes.py:77-160`, `artifacts/routes.py:38-104`, `ws.py:260-265`, `artifacts/store.py` inbox fallback,
`adopt.py:290-293`, `notify/pusher.py:205-285`.)

do:
1. `/tasks…` and `/artifacts…` (list, get, versions, content) check that the object's agent belongs to the caller;
   otherwise 404.
2. `ws.py`'s publisher looks up the person from the task's or artifact's agent, so only `ws.py` changes; nobody gets
   another person's events.
3. An artifact without a task goes to its own agent's Inbox. An adopted session goes to the owner's agent (only the
   owner has an adopt token). A push with no person (usage, self-change alerts) goes to the owner's phones only.
4. Self-change approvals are owner-only: a family helper's PR on `shbunder/marcel` is shown to the owner, never
   approved by the member.
done when:
- [ ] An isolation test loops over **every** route in the app with an id in its path (not a fixed list): user B gets
      404 on each of user A's objects. A new route with an id must be classified or the test fails.
- [ ] Removing the check from any one router makes it fail; B receives none of A's WebSocket events.
- [ ] A member approving a self-change gets 403; removing that check fails a test.
