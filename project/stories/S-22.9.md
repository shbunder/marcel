# S-22.9 — Updates for every install

A colleague's install follows the published `main` of `shbunder/marcel` and cannot merge into it. ADR-013
Consequences. Opens a PR for the owner (ADR-012: self-change path).

do:
1. `marcel update`: reads `origin/main`'s commit with `git ls-remote`, and when it is newer than the deployed copy,
   writes it to `~/.marcel/state/redeploy.flag` — the same flag the hub writes, so the same checks, health and rollback
   run (S-22.7). It never runs `redeploy.sh` itself. "Already up to date" otherwise.
2. Hub setting `self_change_repo` (default `shbunder/marcel`). Self-change cards only redeploy when the PR is in that
   repository (ADR-005 unchanged). `marcel install` sets it empty when `origin` is not pushable, so on a colleague's
   install a merged PR never redeploys; their updates come from `marcel update`.
3. `docs/operating.md` § Updates: `marcel update` for everyone; self-changes on the owner's install.
done when:
- [ ] Tests: with `self_change_repo` empty, a merged and approved PR writes no flag (removing the check fails a test);
      the default keeps today's behaviour (`hub/tests/test_selfmod.py` unchanged and green).
- [ ] On the NUC with `MARCEL_REDEPLOY_BRANCH` pointed at a drill branch: `marcel update` deploys its head through the
      flag; the redeploy log shows the usual health check.
