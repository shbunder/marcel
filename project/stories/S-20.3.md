# S-20.3 — Only the kickoff quest sets a project's tracker, and only to a claude.ai artifact

S-20.2 let any quest's `report(artifact, kind=link, role=tracker)` with any `https://` url set or replace a project's
tracker. Contract S-02.13 (app-api 0.8.0, brain-api 0.1.5, channel `Artifact.role`) tightens it: the url is
`https://claude.ai/artifact/<id>` or `https://claude.ai/code/artifact/<id>` and nothing else, and only the
project's kickoff quest may set or replace it. So a quest that goes wrong, or text a quest read on a web page,
cannot point the project's tracker somewhere else.

do:
1. **Mark the kickoff quest.** brain-api `NewTask.kickoff` (boolean; needs `project`, 400 without it): the hub
   stores it on the task (`Task.kickoff`, a migration, default false; not in app-api's `Task`). `tasks_spawn` in
   `plugins/marcel/tools` takes `kickoff` and passes it on; the `project-kickoff` skill says to set it.
2. **Check the url.** `channel/frames.py`: a `role: tracker` artifact whose url does not match
   `^https://claude\.ai/(code/)?artifact/[A-Za-z0-9_-]+$` is a bad frame, refused with an error ack that says
   "a tracker is a claude.ai artifact link". The channel server's `report` tool (`tools.ts`) checks the same before
   sending, with the same words.
3. **Check who sets it.** `projects/store.py` `set_tracker`: only a task with `kickoff` true, in that project, sets
   or replaces `tracker_url`. Any other task's tracker report is refused with an error ack ("Only the project's
   kickoff quest sets its tracker.") and the tracker stays as it was; the hub logs one line naming the task.
4. `hub/README.md` § Projects (trackers): the two rules.
done when:
- [ ] Hub test: a non-claude.ai tracker url (e.g. `https://github.com/a/b/issues`, `https://claude.ai.evil.example/artifact/x`)
      is refused with an error ack and `tracker_url` is unchanged.
- [ ] Hub test: a tracker report from a quest that is not the project's kickoff quest is refused and does not replace
      the kickoff's tracker; the kickoff quest's second report does replace it. Deleting the kickoff check fails this
      test (inert-controls rule).
- [ ] Hub test: `POST /brain/tasks` with `kickoff: true` and no `project` → 400.
- [ ] `make -C hub check`, `make -C plugins/marcel/tools check` and `npm run check` in `plugins/marcel/channel` pass.
