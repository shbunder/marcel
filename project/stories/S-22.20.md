# S-22.20 — The hub drives a runner over the computer link

`contracts/machine-link.md` (S-02.14). The hub talks to a second computer's runner exactly as to its own, over the
link that computer opened.

do:
1. `wss://…/api/machines/link` with the machine token. One live link per computer (a new one replaces the old).
2. `RunnerClient` gets a transport per computer: the unix socket for the hub's own, the link for the others. The
   `/events` and tail streams ride `runner.chunk` frames; `RunnerWatch` runs one watch per online computer; a link that
   goes silent puts that computer's live tasks in `unknown` with one alert naming the computer, as a lost runner does
   today.
3. `local.open` frames: `kind: channel` is handed to the channel gateway as if the session connected on
   `127.0.0.1:7420/channel`, with one extra check: the session id must be one this computer's runner started.
   `kind: http` reaches only `/channel/session-end` and `/brain/…` (the routes the plugin calls on its own computer),
   never `/api/*` app routes.
done when:
- [ ] Tests with a fake link client: spawn, list, tail and stop over the link match the same calls over the socket
      (shared test cases with `test_runner_client.py`); a channel `hello` for a session id the link's computer did not
      start is refused (removing the check fails the test); an `http` frame to an app route is refused.
