# S-22.16 — The app gets pushes through the relay

So every install gets pushes without its own APNs key (ADR-013 question 2). **Before it can close:** the owner has
deployed the relay (`relay/README.md`, S-22.14) and has the Apple developer account (B-18).

New files: `ios/Config/Marcel.entitlements` (push, the shared keychain group `$(AppIdentifierPrefix)marcel.push`) and
`ios/Config/NotificationService.entitlements` (the same keychain group); the extension target is added to
`ios/Marcel.xcodeproj` with Xcode, not by hand-editing the project file. *(2026-10-24, implementer: an agent session
cannot drive Xcode, so the target was added in the project file's own hand-written style and `make -C ios app` builds
it; the owner opens the project in Xcode once at the signing step to confirm both targets.)*

do:
1. When notifications are turned on: get the APNs token, `POST <MARCEL_RELAY_URL>/v1/register`, make an X25519 key
   pair with CryptoKit (private key in the Keychain, in an access group shared with the extension), then
   `PUT /devices/{id}/push` `{kind: relay, relay_url, handle, send_secret, device_key}`. ntfy stays the choice when
   the relay cannot be reached ("Notifications through ntfy: install the ntfy app").
2. New target `ios/NotificationService/` (a Notification Service Extension): opens `sealed` with the private key and
   shows the real title and body and the `link`; on any failure it leaves "You have news".
3. `MARCEL_RELAY_URL` in `ios/Config/` (the owner's Worker address, S-22.14 README).
4. Sign out deletes the handle (`DELETE /v1/handles/{handle}`) and the key.
done when:
- [ ] `make ios-check` passes; a test opens the contract's known-answer `SealedPush` with its fixed key
      (`contracts/tests/fixtures/`), and a corrupted one falls back to "You have news".
- [ ] On a real iPhone with the TestFlight-signed build and the owner's relay: a quest finishing on the Mac shows its
      real title on the lock screen (screenshot in the commit).
