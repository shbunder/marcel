# S-12.14 — Project room groups quests like Claude Code Projects

ADR-011: Marcel borrows the Overview groups of Claude Code Projects, so an owner who uses both sees the same words.
No new task state and no contract change: the groups come from each task's `state` and its `pr` artifact
(app-api `Artifact.pr.state`).

read first: project/decisions/ADR-011-marcel-and-claude-code-projects.md, contracts/task-states.md,
contracts/app-api.yaml (`Task`, `Artifact.pr`), project/stories/S-12.7.md.

do:
1. In the project room (`ios/Marcel/Map/`), replace "quests by state" with five groups, in this order, each hidden
   when empty:
   - **Needs you**: `needs_you`;
   - **Working**: `queued`, `starting`, `working`, `silent`, `unknown`;
   - a `done` task goes by its PR artifacts: any `open` or `draft` PR → **Ready for review**; otherwise any
     `merged` PR → **Done**; otherwise (every PR `closed`) → **Ended**; no PR → **Done**;
   - **Ended**: `failed` or `stopped`.
2. The grouping is one pure function (task + its PR artifacts → group), so the Quests tab can reuse it later.
done when:
- [ ] Unit test of the grouping function: one task per state, and `done` tasks with no PR, one open, one draft, one
  merged, one closed, merged + closed (→ Done) and merged + open (→ Ready for review).
- [ ] UI test on the mock hub: a project with a task in each group shows the five headings in order.
- [ ] `make ios-check` green.
