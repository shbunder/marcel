Marcel App Wireframes

How you would use Marcel day to day: one conversation with Marcel, threads that do the work (shown as quests), projects that group them, and artifacts you read instead of scrolling. Drawn in the pixel-classic style. Screens scroll sideways inside each flow.

THE MODELFour things, one hierarchy

This is the same shape as Anthropic's new Claude Code Projects (a coordinator conversation that hands work to threads), with Marcel's main chat sitting one level above projects.

MARCEL · the main chat

One conversation that never resets. Marcel answers small things itself and turns anything substantial into a thread. It shows only milestones and rich cards.

THREADS · quests

Each thread is its own Claude Code session doing one job. You can open it, watch it and talk to it. It reports back: started, needs you, done (with artifacts), failed.

PROJECTS · the map

A project groups threads, artifacts, notes and instructions around a goal ("Home energy", "Marcel dev"). Coding projects can later be backed by a Claude Code Project.

ARTIFACTS · items

The things threads produce: comparisons, plans, status boards, PRs. Living documents that update in place, so you read the latest state instead of the chat.

YOU ▸ MARCEL (main chat) ▸ PROJECT ▸ THREAD ▸ ARTIFACT  ·  reports flow back up as milestones; the full detail stays in the thread

YOUR QUESTIONSWhat I recommend

1 · One continuous chat?

Yes. One chat with Marcel is home, as the plan says (B-01). Rich content lives in it as cards: thread cards, approvals as choice prompts, artifact cards, digests.

SEE FLOW 1

2 · Interactive threads? Is Marcel aware?

Yes, threads are interactive: open one to watch it and type to it, or reply-in-thread on any message. Marcel stays aware the way Claude Code Projects do: from each thread's reports, a task registry and project notes, not by rereading transcripts. Its own context rolls over; your transcript never changes. Muse doesn't publish how it does this; its chat is a single stream with an activity trail.

SEE FLOWS 2 AND 6

3 · Claude projects?

Give Marcel the same project model and map it to Claude where Claude allows it. Today claude.ai Projects can't be used by another app, and Claude Code Projects are web and desktop only (beta). So v1 keeps projects in Marcel (goal, repo or folder, instructions, notes, library), and later hands coding work to a linked Claude Code Project.

SEE FLOW 5

4 · Artifacts?

Every "done" milestone carries its artifacts. Status boards and overviews are living artifacts: republished in place when things change, pinned on their project, and collected in the Library. Following a project means reading its board, not the chat.

SEE FLOW 4

FLOW 6How Marcel stays aware

Marcel's own context stays small: it reads thread reports, a task registry and project notes, never full transcripts. It rolls its context over when it gets long; your chat history does not change.
